# FORGE → Yggdrasil CKAD development execution agreement

The F139 original owner may specify an immutable, bounded CKAD campaign in
its existing original-owner state. The developer contract is not a grant to
launch new controllers, worker queues or new scientific first-use.

Source pins for existing CKAD13 and newly qualified CKAD24 are explicit
developer allowlists; source qualification does not confer run authority.

The new f139/ckad_development_order_adapter.py translates a verified
SingleOwner proposal for a *learn* phase into Yggdrasil's exact native stage
input schema (no unbounded arbitrary path, old-source substitution, evaluator
phase masquerading as training or larger than 120-second per-stage budget).
Original source sha, campaign sha, frozen checkpoint sha, source tree,
evidence packet sha, observed budget and research owner must all agree.

All output flags are INERT. Neither the existence of a GitHub workflow,
successful CI nor this adapter grants source-authenticated original training,
runner actions, first-use, model promotion or a persistent live scientific
campaign. A separately authenticated Yggdrasil source-owner permit must be
issued before the F139 worker may actually schedule work. The developer
campaign evidence is retained as GitHub run artifacts, with no live owner
installation and no first-use data.

The Yggdrasil CKAD25 developer-only workflow produces genuine two-stage
native train/cold-restore artifacts plus held synthetic evaluation. That
workflow runs on its isolated research branch and does not connect itself
to the live F139 owner. To complete deployment, authenticate the original
owner's exact-source request and the Yggdrasil scientific permit, bind
persistent learned checkpoint custody and independent evaluation, then
qualify original-owner lifecycle cutover without replay.
