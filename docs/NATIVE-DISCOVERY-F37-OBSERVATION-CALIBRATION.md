## Narrow, falsifiable question

F36's `f36Model.observe` uses a deterministic learned event template with a zero-support fallback: if all prior believed states produce zero probability for new noisy sensors, it retains the prior under the predicted XOR event and fabricates fixed evidence likelihood `1e-9`. The true physical sensors are generated by the exact `f36Likelihood` channel, so this zero probability can arise from **overconfident latent-state / transition hypotheses**, not from a necessarily incorrect sensor model. Does a *proper, fixed 2.5% contamination of the predicted 16-state transition distribution* reduce prequential observation NLL without oracle truth or unnormalized fallback?

At each real model step, after propagating the predicted state through each pending event, define `prior_epsilon(state) = 0.975 * prior_deterministic(state) + 0.025/16`. Multiply it by **unchanged** `f36Likelihood(two actual sensors, state)`, sum exact marginal likelihood, then normalize the posterior. Update the four learned-template weights using the same original F36 5% hazard and the resulting sensor marginal likelihood. All issued-event receipts remain immutable and event law/hypothesis selection and F36 goal planning are unchanged. The calibrated filter NEVER accesses simulator clean state, latent regime, or counterfactual outcomes. The contamination is an explicitly misspecification-robust **state transition** model, not a changed sensor likelihood and not evidence of a physical 2.5% noise event.
