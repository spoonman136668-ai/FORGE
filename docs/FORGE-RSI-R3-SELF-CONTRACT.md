# FORGE RSI-R3 — FORGE-self source-candidate **development boundary**

This is an isolated, inert **engineering source compiler and verifier**, not a new owner capability. It cannot run a candidate, select an external task, check out a repository, dispatch a worker, alter F139 SQLite, grant a research first-use, authorize a merge, or install anything. Its output has `eligible_for_owner=false`, `scientific_first_use=false`, `deployment_authorized=false`, and `rsi_proven=false` regardless of engineering qualification.

## Frozen source and custody

Pinned baseline commit `e48693e41347942c2b581c2fa2793406020b7b67`; tree `7047c3ec1b6ef92064044c7020cf10155f6bbda5`; target only `f139/nci04_portfolio_source_boundary.py`, raw Git blob `8bb13f14f6039032cde4aca623a38713ea47b4e9`. No other target path, parent, source bytes, or free-form Python text are accepted. Only one fully reviewed edit kind, `reuse-unchanged-ast-identity`, can emit source. It reuses the already parsed original AST identity for exactly identical candidate source bytes, without importing packages, executing a candidate, or changing any unrelated function. The compiler validates exact binary preimage, AST change locality, output bound, and deterministic receipt. The caller supplies a consumed-source filter; this is **not independently authenticated complete historical custody**, so it cannot approve owner execution.

The mandatory qualification inventory retains the existing focused source validator tests, complete F139 Python tests, Go tests, vet and build. Existing hosted Linux/Windows PR CI performs source-level regression; no duplicate manually dispatched workflow. This proposal does **not** modify those workflows or their original owner. The new edit is a proposed source alternative, **not** an asserted performance benefit, RSI gain, scientific proof, or authorized installed-source change.

## Why this gate is necessary, and what it does not establish

Prior #1538 policy search, #1539 real test-discovery two generations and #1554 authenticated source workload preserve scientifically/engineering-relevant negatives; #1554 was closed NO_GO: no >=10% G1 and additional >=10% G2 gain against the strongest conventional cache control across both OS. The F139 original candidate contract currently supports Wingless/Yggdrasil only; it is incorrect to infer that autonomous FORGE source-editing is deployed. This new independent contract starts from **one actual operational FORGE source function** without widening that original contract or owner permissions.

The *next* actual proof experiment needs **new, unused** authentic engineering tasks and at least two independently source-qualified generations in disposable FORGE trees, selected by native source before seeing heldout tests. Freeze the strongest normal/source-cache/static repair controls, exact-source heldout task identities, matched compute and action budgets, external negative controls, wall/CPU/RSS including author+qualification costs, and >=1.10x per-generation improvement threshold *before* first-use. The first generated generation must demonstrably change subsequent source generation and downstream performance, rather than replay a fixed operator. Any null result stays NO_GO; no tune/reuse of #1539 or #1554 heldouts. Confirm project-scoped original-owner self-source authority separately before any owner activation. Never use CKB-plane, a new scheduler, an additional controller, paid APIs, or interrupt Wingless/Yggdrasil research.
