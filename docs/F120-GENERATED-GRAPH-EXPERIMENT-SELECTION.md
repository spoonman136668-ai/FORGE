# F120: Generated-environment development qualification

**Scope:** F120 evaluates concrete GenEnv graph-challenge vectors on public synthetic source-disjoint conditions, not unimplemented scientific mechanism hash claims.

The protocol was frozen in commit b8a156b1e3ab893741f47ac3737dd7723316813f before source changes, from protected main 07e9e0903064226f7903c83b12a3bce631ae17bb. F120 keeps the original generated artifact SHA identities linked to the F94 proposal SHA claims.

The model-free generator now emits two real prompt strings and two GenEnv numeric vectors per lane. F120 evaluates the two environments with typed graph-binding controls on 24 TRAIN counterfactual pairs per candidate, selects the more discriminating *challenge environment* using only TRAIN, and evaluates both candidates on a disjoint 48-pair CONFIRM cohort. The three controls are a strong exact binding oracle, a depth-2 limited symbolic binder and a role-only graph matcher. Every positive/negative graph pair shares topology, with a single variable-link mismatch in the negative.

This is actual candidate-specific **research-development environment testing** and bounded evidence-based selection. A full symbolic binder is expected to perform well; selection of a challenge that defeats a depth-limited baseline is not evidence of a new learned mechanism or original science.

The existing six-hour integrated GitHub workflow performs F120 after F118/F119 model-free engineering feedback stages. Results and SHA-256 receipts are archived on both operating systems. No new scheduler, Codex, paid inference, original scientific dispatch, accepted-ref mutation, optimizer promotion, CKB-plane or Cloudflare write. Genuine scientific model improvement and consecutive unattended scheduled-run evidence remain separate qualifications.
