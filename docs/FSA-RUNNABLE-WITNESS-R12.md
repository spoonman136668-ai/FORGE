# FORGE FSA R12 — runnable read-only signed-witness service

**Status: executable service source available; NOT deployed, signed, provisioned, independently hosted, or activated in production. Scientific authority remains with the existing CKB-plane owner.**

R12 converts the previously source-only `fsawitnessstore` and `fsaservice.WitnessHandler` into a **runnable, dedicated FORGE witness HTTPS process**:

```
go build -o forge-fsa-witness ./cmd/forge-fsa-witness
forge-fsa-witness -config /absolute/protected/path/witness-public-config.json
```

No server is started by GitHub Actions qualification, no credentials are created by this command, and there is no default listener. A missing, malformed, stale, untrusted or incomplete configuration prevents startup.

## Explicit provisioned config contract

`witnesshost.Config` (`forge.fsa.readonly-witness-host.v1`) requires the following externally pinned fields, all without defaults:

- `listen_address`: explicit **IP:port**; loopback by default. Setting `allow_remote=true` permits an explicitly chosen remote interface but DOES NOT prove a protected network boundary.
- `witness_root`: absolute existing `forge-fsa-witness` directory, created previously from an independently signed genesis witness via `fsawitnessstore.Provision`.
- `archive_id`, `key_id`, `authority_public_key_hex`, `authority_epoch`, `binding_sha256`, `witness_public_key_hex`, `minimum_revision`: separately obtained immutable FSA identity and minimum independently retained signed revision.
- `allowed_client_spki_sha256`: SHA-256 of the **authorized read-only client's** verified leaf-certificate public key.
- `client_ca_file`, `server_cert_file`, `server_key_file`: absolute, independently provided PEM files. The TLS key is never written or generated by FORGE source. On Unix, the key must be inaccessible to group/other users.

Use a canonical JSON document with no duplicate or unknown fields, with at most a single trailing newline. Place config, TLS keys and service files outside the public repository, CKB-plane, KTRADE, the scientific archive and worker directories.

## Runtime properties

- Requires TLS 1.3, a valid non-CA server certificate, a trusted client chain **and** the separately pinned client SPKI. No unauthenticated TLS/plain HTTP fallback exists.
- Serves only `GET /v1/fsa/highwater?archive_id=...` from **already signed** witness records. Unknown paths and all writes reject; no signing, checkpoint CAS, step consumption or execution route exists in this binary.
- Revalidates the complete local canonical witness chain, Ed25519 signatures and high-water progression on each read. The running process poisons itself on detected rollback/corruption. Restart requires the independently protected *current* `minimum_revision`; do not derive this floor from the restored local witness directory.
- Enforces bounded headers, timeouts, explicit network binding and graceful signal-triggered shutdown. No password, token, environment-secret ingestion, queue consumer or worker dispatcher.
- The process is intended for a **separate trusted host and failure domain**. Running this alongside authority on the same machine does NOT establish independence.

## Qualification and next deployment gate

Full Linux testing (including race), vet, build and native Windows tests/vet/build, plus a **real TCP TLS 1.3 mutual-TLS integration** of the same handler and store are required. The test validates signed revision 1 and 2, wrong client SPKI denial, no-client-certificate rejection, read-only routes, on-disk signed valid-tail rollback and independently pinned restart floor. It uses disposable synthetic keys.

**Still blocked before science:** a separately deployable protected FSA checkpoint-authority service, real independent physical archive-binding attestor, external high-water ledger and key custody, signer separation, atomic cross-host CAS and worker action-level fencing, actual original-first-use custody and controlled revocation/cutover. Deployment may require an operator-controlled independent host, protected OS service identities and networking unavailable from this chat. Do not infer deployment or operational science from a green PR.
