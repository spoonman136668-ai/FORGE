# F118 — Autonomy-first model-free source feedback (engineering-development only)

## Intent and preserved boundary

F118 intentionally returns FORGE's development priorities to **autonomy**. The existing integrated two-lane six-hour GitHub Action already runs model-free Promptbreeder/GenEnv proposal generation and synthetic development workers, but until F118 it did not automatically select **an action from the proposals**, execute it, persist the result, and use that feedback to change a subsequent unattended action. F118 adds that missing *bounded engineering-development feedback stage* to the **same** scheduled worker. It does **not** install a second scheduler, use Codex/paid GPT inference, or authorize scientific original execution.

The freeze was committed **before F118 executable code**: [b4d8f109](https://github.com/spoonman136668-ai/FORGE/commit/b4d8f10913e74184ed04f3177ae569dc303c56f3) from main head `8b8b9a162d947e0e773128d2268744342f1c2ba1`.

## Actual decision-and-action loop

Each runner reads its **current same-commit** `forge-model-free-advisory.json` generated by the existing native source-only mechanism. The advisory must contain exactly four globally distinct SHA-256 proposal IDs in each of two separate Wingless/Yggdrasil lanes, all labelled **UNTESTED**, with the historical negative/invalid/mixed records preserved and zero accepted science.

F118 chooses the next candidate *per lane* using an explicit, deterministic, bounded feedback policy:

1. Retry a recent unsuccessful engineering check once (with a hard two-failure cap), otherwise select the candidate least often checked.
2. Execute the selected **allowlisted Go unit-test suite** with a hard 90-second timeout. Only `promptlineage`, `genenv`, `optimizerstages`, `evoportfolio` or `dreamrsi` may run, and only as **development readiness tests**. These checks do **not** scientifically evaluate the proposed mechanism.
3. Preserve PASS/FAIL/TIMEOUT, source-bound proposal ID, suite, exit code and stdout digest. A failure is an input to the next selection; it must not be hidden.
4. After the workflow completes successfully, publish a separate `forge-f118-feedback-ubuntu-latest` artifact (`state.json` plus exact SHA-256 receipt) alongside the existing evidence.
5. On the **next genuine scheduled main run**, retrieve the most recent successful scheduled-main artifact through GitHub's own Actions API. Verify that run's event, branch, SHA, attempt, success status, strictly older run ID, entire receipt and stored continuity state before using any historical feedback. PR, push and manual runs cannot satisfy unattended continuity.

The two-lane executions are real GitHub-hosted package tests; a **successful unit test is not evidence that the candidate's hypothesis was tested or improved**. Frozen fixture-generated proposal identities do not constitute novel scientific hypotheses. This F118 gate demonstrates closed-loop **engineering task selection and execution**; scientific hypothesis quality remains a separately gated question.

## What counts as qualification

- A PR test-merge can prove selection behavior, hostile-state quarantines, retry/rotation, real two-lane package test execution and artifact integrity, but **cannot** prove two completed *unattended scheduled* runs.
- The first scheduled main run after merge starts from no F118 history and must report `BOOTSTRAP_NO_PREVIOUS_F118_ARTIFACT`.
- The second new completed scheduled main run may report `VERIFIED_PREVIOUS_SCHEDULED_RESULT` if it consumed the real previous saved outcome and selected a different candidate or bounded retry based on that outcome.
- Demonstrating **two real consecutive scheduled GitHub-hosted runs** after guarded integration is the follow-up operational acceptance. Synthetic unit test simulations of two iterations are not substituted for it.

## Security and scientific limitations

No privileged science, Wingless/Yggdrasil repository writes, controller deployment, accepted-ref mutation, optimizer promotion, FSA grants, Model API, Codex, ChatGPT Work, CKB-plane or Cloudflare contact. Read-only Mind-Palace integration remains separate. This is a **model-free autonomous engineering-development loop**, not full autonomous scientific research or genuine Dream-RSI policy improvement. Future gates should plug in real, independently source-validated experimental outcomes to candidate ranking, without removing these restrictions.

F118 is staged in a draft PR against main. The existing six-hour schedule becomes active **only after** guarded merging; it must not be described as live on main before that occurs.
