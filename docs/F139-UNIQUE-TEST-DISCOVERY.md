# Preserve distinct regression coverage; remove repeated fixture discovery

Python unittest discovers TestCase objects exported by importing test modules, including fixture classes imported only for setup. The existing command therefore executes identical test IDs multiple times. This change uses module-qualified fixture access instead of exposing the same TestCase repeatedly. It retains one canonical exposure for each existing raw test ID, including distinct package/module identities; no assertions, test methods, fixture behavior, skip rules, production source or controller authority change.

Baseline: b5172a047efa7a1d630c15c13a2b7eba14c997fe. Development-only collection: 1,744 executions -> 1,339 executions; exactly the same 1,339 distinct IDs; 405 duplicate executions removed. These counts are not execution PASS or a speedup claim.

Existing public Linux/Windows qualification performs one same-host baseline/candidate full Python regression comparison on this optimization branch, in separate Python processes with inherited matching resource limits. Windows runs candidate first; Linux runs baseline first. Existing native qualification independently compares inventories and runs the complete candidate regression, including platform controls. Go/race/vet/build, integrations, scientific controls and mandatory final regression remain in their existing jobs. No additional runner, workflow, controller or scheduler. Normal branches retain the existing full-regression command.

The bounded checker rejects imports that fail collection, missing/added IDs, duplicates, changed skip identities, source drift, test module changes and AST body changes after resolving only fixture-class imports and qualified uses. Three collection and three semantic falsification controls retain assertions, setup/cleanup calls and skip decorators. Exact source/tree, checker hash, normalized-body hash, Python/platform identities, execution order, outcomes and timing receipts are uploaded by the existing workflows. Full local regression is disabled; only hosted qualification may execute the paired suites.

One pair per platform is a development measurement, not a repeated performance claim or evidence of scientific improvement. Record observed suite ratios and full-job durations separately; do not infer a 2x improvement or reuse incompatible evidence. Qualification infrastructure only: installed owner, source policy, negative custody, scientific first use and accepted research state remain unchanged.
