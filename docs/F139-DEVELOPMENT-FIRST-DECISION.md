# F139 — Development-first private cognition research

**Decision:** owner-approved 2026-10-20. Scope: FORGE's autonomous development
lane only. This is a priority correction, not an admission, deployment, protected
scientific permit, or production source promotion.

## Operational mode boundary

| Mode | Permitted work | Witness/FSA | Evidence and admission |
|---|---|---|---|
| Private development | Architecture implementation, exploratory training with explicitly development-only data, code review, developer simulations, ablations, nonprotected regression tests | **Not required** | Exact source/branch/diff, executable receipt, deterministic test inputs, comparators, resource budget, negatives |
| Protected science | Sealed unseen originals, frozen scientific holdouts, first-use claims, accepted reference/policy promotion | **Required under existing FSA policy** | Independently authenticated owner/witness, complete consumed/active/uncertain ledger, guarded worker boundary, rollback/recovery |
| Synthetic rehearsal | Existing `forge-model-free-loop --synthetic-only`, source-only readiness and D2K package diagnostics | Not required | Must remain labeled synthetic or diagnostic; **not** new learned-cognition progress |

Development evidence is never automatically promoted to the protected-science mode.
No change to the protections in `AGENTS.md`, existing FSA code, locked studies,
first-use records or negative evidence is implied by this decision.

## North Star — productive engineering rather than infrastructure gates

- **Wingless:** implement and measure a native, trainable persistent state
  update/retention mechanism in the actual Wingless execution path. Show the
  effect of learning and persistence through ablations and a fully trained,
  equally informed stateful baseline; retain equal-or-lower CPU and memory
  accounting. Keep model training and testing in explicitly development-only
  cohorts until scientific first-use is separately qualified.
- **Yggdrasil:** implement and measure learned online entity bindings and
  causal relation updates across sequential events in the actual Yggdrasil
  system. Test composition and counterfactual use against trained recurrent
  and symbolic baselines, with intervention and memory ablations, equal
  information/budget and negative retention. No frozen holdout consumption.
- **FORGE:** own bounded discovery/dispatch/recovery for actual developer
  tasks; require source-pinned result code and measurements. Do not duplicate
  the Wingless/Yggdrasil scientific study owners or deploy a new controller.

A milestone only counts toward the private-development goal when there is a
source-linked mechanism implementation, a genuinely executed development test
or training run, honest negative/positive evidence, and repeatable resource
accounting. Green synthetic workflows, scheduler pulses, paper designs, and
untested source-only proposals count as **readiness**, not learned cognition.

## Existing infrastructure and the actual remaining gap

The F139 controller already has one owner, a durable local SQLite queue,
HMAC-bound tickets, start-risk/no-replay logic, authenticated GitHub-hosted
workers and two-lane development labels. Those controls are valuable and
should be reused.

The normal worker still runs a *synthetic* model-free advisory. D2K can run
allowlisted FORGE package tests, not modify or train the Wingless/Yggdrasil
architectures. Genuine unattended cognition engineering requires a separately
qualified **development-only task adapter** that produces actual source diffs
and/or development-data training outcomes under an existing authority.
Implement that adapter in the current F139 execution path; no new dispatcher,
science owner, Cloudflare schema, external witness, paid model API or Kboomllc
resources should be introduced.

## Acceptance for the next adapter

1. Verify the exact authenticated owner task, FORGE protected-main SHA,
   downstream program source SHA, bounded dev-data identity, and allowed
   mechanism/test budget **before** any work. Only allow approved sandboxed
   development operations. No protected first-use, sealed test access,
   external brokerage, or arbitrary task commands.
2. Do genuine mechanism development (not `--synthetic-only`), run focused
   tests/training with matched baselines, and capture full source diff,
   runtime, RAM, accuracy and negatives. Preserve untouched historical records.
3. Keep the original F139 one-shot dispatch and crash ambiguity semantics;
   never reissue a possibly started task to make the dashboard green.
4. Independently re-read the committed branch and worker results, then one
   full qualified regression before any source promotion. A source-only
   diagnostic without a mechanism change must remain clearly labeled.
5. Do **not** merge/promote science or mark experimental originals available.
   A future separately authorized science gate may reuse **only** qualified
   development learnings, never pretend its protected first-use happened.

## Explicit stop-work

Pause new independent-witness provisioning/Cloudflare FSA schema migrations
as development prerequisites. Do not delete the existing Cloudflare archives,
operator public pin, recovery state, source-only witness implementations,
or previously qualified custodial evidence.

No existing scheduled controller or research workflow is disabled, and no
new scheduled behavior, secret, key or bill is created by this decision.
