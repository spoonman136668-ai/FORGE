## New, falsifiable mechanism
Hypothesis: a **provably conservative two-stage exact top-1 vocabulary head** can avoid evaluating most of the 50,257 GPT-2 output-token dot products. Precompute norms on the **unchanged** tied pretrained LM-head weight tensor, rank tokens using a fixed low-dimensional partial dot product, then use Cauchy–Schwarz residual score upper bounds to disqualify tokens **only when their best possible full score is strictly below the best verified full score**. Compute every uncertain token's full dot product, or fall back to the same full-head reference when certification would be expensive. Do not use the true next token, output label, future hidden states, stored answer or heldout results in selection; no learned index, fitted projector, or approximate answer acceptance.
- Original GPT-2 weight `W\in R^{50257x768}`, final transformer hidden `h\in R^{768}`; original reference is `torch.nn.functional.linear(h, W)` and strict argmax token (lowest index on exact tie). Model weights and torch FP32 remain unchanged. Frozen partition: first **384** hidden coordinates partially scored; 384 residual coordinates bounded by stored per-token residual weight L2 norms times per-request residual hidden L2 norm. Seed **64** partial-score top candidates (deterministic tie handling); compute their exact full scores to establish incumbent. Every omitted token whose upper bound cannot safely exclude it must be fully scored, with index-aware conservative tie handling. If > **8192** tokens remain uncertain, run full reference head (must be counted as fallback), never claim certification savings. The conservative numerical guard is `0.001*(abs(partial_score)+abs(residual_bound)+abs(incumbent)+1)`. Exclusion requires `partial+bound+guard < incumbent` (strict). Always compare candidate argmax against the independent full `F.linear` oracle; any mismatch = FAIL_EXACTNESS and no speedup acceptance.
- Precomputation of residual token L2 norms must be charged in an **amortized** total. Reference and candidate output projection are both timed, including candidate upper-bound computation and dispatch overhead. Report number of pruned and exact-scored tokens, fallback count, norm construction wall and peak/sampled process RSS. No cached true token, prompt duplication or favorable score-selection after results.
