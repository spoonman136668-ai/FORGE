# ACC-61 — original U01 JIT tensor decompression — prospective protocol

**Identity and source custody before code or data.** Original `research/ac07_sourcefree/ac08_portfolio.py` Git blob `5126c860771fb024ccfc14c3f7ee8925edf29787` lists one-based U01 **JIT tensor decompression**. Research base `45b5d8173538a566bf0f63a8e2ade2dedb6e6166`. Freeze this plan before implementation and prohibit post-hoc threshold edits.

**Hypothesis.** For exactly equivalent int8 matrix-vector inference, decompressing a compact fixed tensor on demand can reduce actual full-process memory with competitive CPU versus storing dense weights. This is *runtime decompression in native Go*, not compiler JIT unless a distinct actual JIT backend is demonstrated. The hypothesis name is historical, not a verified mechanism.

**Ground truth and task:** four fixed synthetic tensor regimes N=64,128,256,512 square; public five seeds 161101,161103,161107,161109,161111. For each seed/size independently generate int8 signed weight matrices with an explicitly frozen 16-value palette and a deterministic structured repeat pattern allowing lossless RLE; generate 4096 independent input vectors per cold child with public deterministic PRNG. Compute exact signed int64 output rows for each arm, with independent scalar dense reference. Preserve original weight SHA256, input SHA256 and full output SHA256 across all arms; no different source or omitted operations. Include a genuinely incompressible random-weight control regime or explicitly restrict conclusions to structured compressible tensors.

**Three actual methods:** DENSE (all weights stored as int8), RLE_PREDECODE (losslessly decode full tensor once, then infer), and RLE_STREAM (decode compressed tensor while multiplying the current input row). Require actual matching outputs for every query. Account for compressed bytes, decoded scratch, weights, binary overhead, full-process CPU and native physical peak RSS. Never label RLE_PREDECODE memory savings if full dense table persists during computation.

**Qualification:** 4 sizes ×5 paired seeds ×3 arms = 60 independent native cold Go child processes per OS; real User+System CPU, wall and peak OS physical RSS, no imputed zeros. A worker may repeat **real inference** three times, identically for all arms, to resolve timer granularity; do not inject unrelated timing-work. Native Go test/vet/build, original 36 research screens, source and prereg-before-code custody, full crossOS 60/60 source/ground truth/prediction parity. Store GitHub Actions artifacts and include exact qualification commit and measured run.

**Frozen positive:** RLE_STREAM must achieve 100% bit-for-bit output equality, >=50% reduction in *actual* measured non-code live working-set bytes attributable to weight representation versus DENSE, OS peak RSS <=0.80× DENSE, and median full-process CPU <=1.10× fastest conventional (DENSE or RLE_PREDECODE) on **all four** regimes and **both OS**.
