# ACC G57 — preregistered from-scratch language-model training-cost screen

**Status:** committed BEFORE benchmark code and BEFORE execution. Isolation: read-only to FORGE autonomy and protected main. Engineering-only; not native-model scientific first use; not user research selection acceptance.

## Data custody
Original public Tiny Shakespeare, `https://raw.githubusercontent.com/karpathy/char-rnn/master/data/tinyshakespeare/input.txt`, **exact 1,115,394 bytes SHA-256 `86c4e6aa9db7c042ec79f339dcb96d42b0075e16b8fc2e86bf0ca57e2dc565ed`** as independently published in `karpathy/tiny_shakespeare` metadata. Every run refuses a mismatch. No alternative corpus on mismatch. One contiguous 80% train, 10% validation, final 10% sealed *never read for training/selection*. Byte-level language model vocab 256; no tokenization cost ambiguity.

## Matched model and training
Small **4-layer, d_model64, 4-head, feedforward128** pre-LN causal Transformer, zero attention/MLP dropout, GELU, learned positional and token embeddings, 256-byte vocabulary, AdamW lr=.002 weight_decay=.01. From scratch and **identical initial seeded weights across arms**. Seeds **1901, 1903, 1907**, exactly one run per arm per seed. Train **120** optimizer updates, batch **8**, sequence length **48**, same deterministic step/seed-specific source offsets independent of arm. Evaluate 96 fixed validation windows at update 0,30,60,90,120; all four layers active for evaluation, including early-grown networks. Baseline must learn; no claim of high-quality LM or transferred capabilities.

## Four arms, no tuning after observations
- baseline: all 4 blocks every update.
- layerdrop: deterministically skip one of four residual blocks per step for first 96/120 updates, full depth last 24; average 20% block-work skip.
- progressive: run only blocks 0,1 for first 54/120 updates; all four last 66; average 22.5% block-work skip.
- combined: blocks 0,1 for steps 0-53; steps 54-95 run 3/4 rotating blocks; steps 96-119 full; average 31.25% block-work skip.

All arms have the same full 4-layer final parameter count, are initialized at full size, and maintain optimizer states for all weights; layer-drop and progressive blocks are not updated when inactive. This is **not a faithful reproduction of published CGLS or tuned layer-drop**, only a fixed schedule falsifier. No adaptive selection or look at held-out test.

## Primary admission threshold
Compared **within each seed** to matched baseline, a candidate qualifies as a narrow CPU *engineering* improvement only if **all three seeds**:
1. final validation cross entropy `candidate_nats <= baseline_nats + 0.05` (absolute nats/token, not relative percent);
2. complete worker **process wall** baseline/candidate >= **1.15x**. Include fresh process Python import/startup, loading public dataset and initialization, optimizer, training and validation. (Pre-download shared corpus excluded for all arms.) Also report training-only wall and CPU time separately;
3. physical process peak RSS candidate <= 1.10x baseline.

Report positive or negative even if no arm qualifies. Do not cherry-pick a single favorable seed; no pooled loss means. Workloads are sequential to prevent contention. Validation does not imply any sealed test/transfer improvement.
