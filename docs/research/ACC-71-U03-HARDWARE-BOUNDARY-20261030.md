## Testable claim split and strict non-equivalence
1. **False as nomenclature:** physical HBM is stacked multi-die hardware with distinct channels/interfaces. Rearranging data layout, mapping addresses, increasing thread count, and simulating memory nodes in software **cannot turn standard DRAM into physical HBM** or create HBM memory channels. This is a category boundary, not a measured throughput rejection.
2. **Plausible software performance hypothesis — OPEN:** NUMA-aware page placement, locality, CPU affinity, memory interleaving, asynchronous prefetch, pipelined memory transfer or tiled operators can improve some existing-hardware workloads relative to an uninformed allocation strategy. These are improvements in **ordinary installed DRAM** and still incur hardware bandwidth/latency ceilings; no throughput or accuracy claim until a physical test.
3. **Not applicable by default:** The owner workstation's physical topology, page placement capability, privileged NUMA controls, full RAM bandwidth, PCIe/GPU memory topology and sustained LLM workload are not verified by GitHub-hosted ephemeral runners. A one-node virtual CI machine or mocked NUMA node cannot prove multi-node hardware characteristics.
