## Hypothesis and controls
U01 claimed just-in-time decompression reduces weight-storage costs without unacceptable inference time. Test this *restricted real compiled Go* data-path analogue rather than pretending compressed bytes run directly as neural weights.

All independent workers synthesize the identical **262,144-byte** public deterministic pseudo-weight array (seed 431, byte order locked). Two fixed cohorts: **REPEATED** (256-byte tile repeated 1024 times) and **RANDOM** (xorshift byte stream, deterministic high-entropy). Explicit source synthesis cost charged **every independent cold session**. Each worker repeats **8 independently cold sessions**; each session performs **16 complete sequential full-buffer "inference" passes**. Every pass uses the SAME deterministic 64-bit arithmetic byte-consumption routine to account for actual bytes consumed, with identical final trace checksum to RAW. No actual neural tensor math, tokens, gradients, KV-cache or model quality is claimed.

Four frozen modes:
- **RAW** strong baseline: keep original uncompressed 262,144 bytes, execute same kernel 16×.
- **JIT** encode the entire buffer by standard Go zlib BestSpeed **charged inside worker**, then open fresh decoder and fully decompress **every one** of 16 passes; decoded output is independently validated length/content and consumed through the same original kernel. No hidden precomputed model parameters.
- **CACHED** encode once (cost charged), decode once (cost charged), retain raw decoded representation for subsequent 16 passes. This deliberately tests whether memory-saving claim survives resident raw cache.
- **STREAM** encode once (cost charged), then repeatedly decompress via a strict 32-KiB streaming buffer, feeding exactly the same byte kernel without allocating an extra full decoded buffer. Track decompressed byte length and integrity. This is the most memory-oriented U01 variant.

All four must generate **bit-identical final complete inference trace checksum** and exactly 262,144 bytes consumed per pass. Corrupted zlib streams, truncated decode and wrong byte count are blockers, not positive compression evidence.
