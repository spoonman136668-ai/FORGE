## Hypothesis and exact-output guard

Can a cheap single-precision output projection suffice on tokens with a high predicted top-2 margin, with rare ambiguous tokens falling back to double precision, **including** casting, norm-bound, routing and verification overhead? For each token first compute `approx_logits=(W.astype(float32) @ x.astype(float32)).astype(float64) + bias`, then measure the top-two gap (stable lowest-index ties). Before accepting a float32 winner, compare the margin to a conservative global rounding budget `B = 4 * gamma_256 * max_i sum_j |W_ij| * max_j |x_j| + 1e-10`, `gamma_256=(256*eps_float32)/(1-256*eps_float32)`. The `max_i sum_j |W_ij|` bound is prepared once for each W and its setup time reported separately; `max_j|x_j|` and sorting are charged on every token. If margin is not strictly above `2B`, recompute full float64 `W @ x + bias` and choose its exact greedy winner. If margin is above 2B, use the float32 winner. `B` is an intentionally generous screening guard, not an independently proved universally valid IEEE-754 certificate; final correctness is audited against full float64 for **every** case and any mismatch is FAIL. No reference output can influence runtime routing.

## Frozen deterministic controls and decision

- NumPy float64 source, one BLAS thread, `W=[512,256]`, 8 independent `N(0,1)` inputs per seed, seeds `[10501,10502,10503]`.
- **`iid`** negative/generalization control: W entries `N(0,1/sqrt(256))` and zero bias, independent of inputs.
- **`hard_near_tie`** deliberately ambiguous control: independent same-scale W, then set row 0 from `N(0,0.01)`, set row 1 equal to row 0 plus independent `N(0,1e-7)` noise; all rows 2+ are scaled by 0.01; add bias 10 to rows 0 and 1, zero elsewhere. Queries generated after W/bias in fixed seeded order. This intentionally makes a near tie; no real-model entropy statistics are inferred.
- Both baseline and candidate operate on the *same* 48 predetermined queries (`3 seeds×2 regimes×8 queries`). Baseline executes exactly one double-precision dense matvec and bias add. Candidate executes full float32 projection and bias, margin selection, bound check, and conditional full double fallback. **No persistent FP32 W cache is permitted**; casting on every query is deliberately charged. Only fixed bound setup is excluded from per-query timings, with its elapsed milliseconds recorded. Data generation excluded for both.
- **9 alternating paired trials** per case after once-warmed arms. Record base/candidate median latency, speedup, selected precision/fallback, observed top-2 gap, bound, exact greedy winner, output winner and parity, and all finite flags. No cases omitted or retuned.
- **NO_GO_SYNTHETIC_SCREEN** unless all 48 greedy tokens match exactly, zero nonfinite cases, and *both* regime medians baseline/candidate speedup **>=1.15×** across 24 cases each. A favorable-only win fails. A conditional pass is **CONDITIONAL_CPU_FEASIBILITY_ONLY**, not a real-GPU result. No change to existing frozen acceptance criteria.
