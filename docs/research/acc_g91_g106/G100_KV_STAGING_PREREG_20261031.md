# ACC-G100 — Predictive cold-KV page staging: frozen cost-model pre-screen

**Status:** preregistered before implementation, measurements or tests. This belongs to GPU LLM-bottleneck exploratory slate G91–G106 on draft PR #1329. It is a deterministic **analytical memory-traffic/event simulation**, NOT a measured transfer, CUDA kernel, GPU speedup, real process, actual NVIDIA DMA or authenticated model test. Do not conflate model-unit costs with hardware milliseconds. Original FORGE baseline `main` `0810ecf3df6378bcbfe5239d30df836b7e12a602`.

## Mechanism and what must be charged

A cold KV page predictor may issue a transfer one event early so its latency overlaps the **current** token's compute rather than stalling the **next** token. No oracle access to held-out next requests. A predictor must be fitted strictly from the first 128 page requests, frozen for the following 384 requests, and may examine only observed prior/current pages. Baseline is a demand-only LRU cache. Candidate is LRU + one predicted prefetch per event; all prefetch traffic, evictions, failed predictions, cache lookups and predictor overhead are accounted. **Both policies must execute the same exact 384 held-out page requests, with no semantic approximation.**

## Frozen controls, hardware-independent model units

- Simulated `PAGE_COUNT=64` pages; each page represents `4096` bytes of KV. LRU cache holds 8 pages, initially empty for every baseline/candidate evaluation. At most one prefetch per event (not one per miss). Prefetch starts *after the demand is serviced* and overlaps **only that current event's** subsequent 1.0-unit compute window. Each cold transfer (demand and prefetch) costs `0.30` time units, so a correct single speculative prefetch finishes during the compute window; no unrealistically unlimited overlap. Demand transfer cannot overlap an earlier compute window unless it was actually predicted and completed. Cache and transfer counters include prefetch evictions and duplicate-transfer avoidance.
- For each seed `[10001,10002,10003]`, freeze two regimes:
  - **`iid`** independent uniform random pages [0..63] for all 512 events — negative control
  - **`cycle16`** draw exactly 16 unique pages without replacement and a random starting offset per seed, then repeat a fixed deterministic 16-page cycle throughout train+test — deliberately favorable, *not observed model behavior*
- Training = first 128 events, evaluation = next 384 (no tuning, no leakage). Two candidate predictors, both frozen before evaluation: **`bigram`** chooses the most common successor to the current page in training, deterministic lowest-page tie, and falls back to the current page if unseen; **`last_page`** always chooses the current page (an intentionally simple control). No evaluation-stream parameter updates.
- Each baseline event cost `1.0` compute unit + `0.30` on a true cache miss. Candidate cost `1.0` compute + `0.30` on a true demand miss + `0.01` predictor/lookup overhead each event, plus any exposed prefetch-overlap cost `max(0, 0.30-1.0)` (zero under this frozen model). Prefetch bytes **always** charged even when fully hidden in compute. No negative latency or overlapping multiple transfers.
- Frozen `3 seeds ×2 regimes ×2 policies=12` 384-event evaluations (4608 held-out request/policy events total), with 3 baseline simulations per regime? Baseline is deterministically recomputed from same 384 requests for each candidate; record all per-case demand misses, prefetch transfers, prefetch-credited next-event hits, total transfer bytes, service page-parity, baseline/candidate model-time units, speedup, prefetch traffic amplification, and whether any speculative eviction caused extra demand. No wall clock timing claim.
- **NO_GO_ANALYTICAL** unless some single frozen policy meets all conditions over **every** of its six seed×regime evaluations: exact serviced request parity 384/384, median model speedup `>=1.15×` **in each regime** across 3 seeds, and **all** six candidate transfer-byte amplification ratios `<=1.20×` baseline. No favorable-only promotion. If one policy passes, label **`CONDITIONAL_ANALYTIC_FEASIBILITY_ONLY`**; still UNVERIFIED on real GPU/cold memory. Nonfinite, missing or invalid counts are FAIL.
- Report the actual request list SHA256 and training-set digest **per seed/regime** (no secrets), frozen parameters and machine-readable case data in the FORGE repository with immutable CI SHA/job. The cost model intentionally favors overlap: it assumes the current token has a full 1.0-unit independent compute window after each demand. A real GPU would require trace-timestamp/DMA/channel contention and residency verification, independent cold-cache controls, bandwidth/RSS and true decode latency before admission.

No paid API, novel controller/runner, protected-main merge, inference-system mutation, accepted baseline change or scientific promotion. Any change to model units, thresholds, capacity or test regime after results requires a new preregistered version.
