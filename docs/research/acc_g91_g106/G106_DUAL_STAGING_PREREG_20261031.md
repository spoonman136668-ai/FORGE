# ACC-G106 — Combined weight/KV predictive staging: frozen analytic pre-screen

**Frozen before implementation or any result.** The final G91–G106 unconventional GPU-bottleneck research candidate on FORGE draft PR #1329. The executable study is a **deterministic two-resource cache/transfer cost model**, not GPU timing, PCIe/DMA capture, authentic LLM or a model-quality evaluation. Independent of the GPT-2 CPU research thread. Protected-main reference SHA `0810ecf3df6378bcbfe5239d30df836b7e12a602`. No accepted baseline, controller, production, model-first-use or main merge authority.

## Distinction from G100

G100 predicted a **single** cold KV resource. G106 explores **coupled weight and KV residency and contention**, tracking two independently capacity-limited LRU caches with a *shared* transfer channel. A predictor may request at most one weight page and one KV page **per completed token**, but transfers must share one channel and both byte counts are charged. Demand misses cannot overlap the current token's computation; a correct prefetch may overlap only a 1.0-unit compute window *after its current demand is serviced*. No lookahead into held-out future requests, no extra speculative channels, no infinite bandwidth and no free evictions.

## Frozen data, policies and costs

- Deterministic NumPy RNG seeds `[10601,10602,10603]`. Each event demands one weight page ID from `[0..31]` and one KV page ID from `[0..63]`. Each original stream contains 512 events, first 128 solely for predictor training, next 384 solely for evaluation. Each evaluation starts with empty caches for both baseline and candidate, without training-stage cache warmup.
- Two **independent** regimes, both mandatory:
  - `iid` negative control draws each weight/KV page from its own independent uniform distribution over 32/64 IDs
  - `coupled_cycle` deliberately favorable: sample 8 distinct weight pages and 16 distinct KV pages independently, plus an independent random starting offset for each, and repeat both cycles for all 512 events. This is manufactured predictability, not actual LLM weights or KV traces.
- Weight LRU capacity **4 pages**, each **16,384 bytes**, demand transfer cost **0.20** units. KV LRU capacity **8 pages**, each **4,096 bytes**, demand transfer cost **0.30** units. Token compute cost **1.0** unit. Predictor/candidate bookkeeping cost **0.02** units per event, including no-op predictions. Candidate's next-event prefetch transfers start after both demanded pages have been serviced, share one DMA lane, and can overlap only the **current** token's compute window; exposed prefetch time cost is `max(0, 0.20*weight_prefetch + 0.30*KV_prefetch - 1.0)`. This is an explicitly **optimistic model**, not clock time. All demand costs remain exposed.
- Frozen candidate policies: `bigram`, a deterministic most-frequent successor map separately fitted for weights and KV from training-only consecutive pairs (lowest-ID ties; unseen page predicts itself), versus `last_page`, which predicts the current page for both resources. Baseline performs no predictions or prefetches. Both policies are fixed before evaluation, no online adaptation, no held-out tuning, no history leakage.
- Exactly **3 seeds ×2 regimes ×2 policies=12** paired 384-event evaluations (4608 held-out token/policy cases). Baseline simulated separately on identical test events. Persist original training/test sequence SHA256 for each seed and regime, exact request-servicing parity, all demand misses, speculative transfers, speculative evictions, next-event credited hits, modeled time units, weight/KV/total transferred bytes, baseline/candidate speedup, and **traffic amplification separately for weight, KV and total**.
- **NO_GO_ANALYTICAL** unless a **single fixed policy** meets all constraints for all six seed/regime evaluations: complete 384/384 exact service parity, both-regime **median modeled baseline/candidate time >=1.15×** over three seeds each, and all weight, KV and combined transfer-byte amplification ratios `<=1.20×` for every evaluation. A favorable-only win is a failure. Any invalid counts, nonfinite costs or missing case fail.
- Conditional label if qualified is `CONDITIONAL_ANALYTIC_FEASIBILITY_ONLY`, never a claim of GPU speedup. A real implementation requires actual model layer timeline, page residency and mutation protection, true CUDA streams, memory capacity, DMA bandwidth and contention measurements, storage/transfer overhead, multiple context traces, full decoder timing and independent scientific first-use qualification.
