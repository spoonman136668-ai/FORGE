# ACC-G96 — Certified attention-block omission: frozen CPU screening preregistration

**State at this commit:** proposed **before** implementation or measurement; scientific acceptance NOT GRANTED. This is a GPU-track *synthetic CPU feasibility proxy*, distinct from GPT-2 CPU research and isolated from G79–G90 PR #1326. Original FORGE baseline: main commit `0810ecf3df6378bcbfe5239d30df836b7e12a602`. G94/G95 qualification remains independent.

## Mechanism, certificate and controls

For a single attention query `q`, divide `N=1024` keys and values into 16 disjoint contiguous blocks of 64. Before query timing, for each key block `g` compute centroid `c_g`, maximum key residual norm `r_g=max_j ||k_j-c_g||`, and maximum value norm `M_g=max_j||v_j||`. During candidate evaluation, `u_g=(q·c_g + ||q||r_g)/sqrt(D)` upper-bounds **every** block score. To account for rounding, inflate this bound by `1e-10*(1+abs(u_g))`. Sort descending bounds. Compute each visited block's actual softmax scores and values; maintain stable streaming softmax sufficient statistics `m, Z, S`. The partial estimate is `p=S/Z`. The as-yet-unvisited softmax numerator is bounded by `R=sum_g 64*exp(u_g-m)`, while unvisited output norms are bounded by `M=max_g M_g`. Therefore true normalized output error has the conservative absolute bound `E<=R/(Z+R)*(||p||+M)`. Stop only when `||p||>E` and `E<=1e-3*(||p||-E)`; otherwise compute more blocks. If none remain, use the exact fully accumulated output.

**This bounds output-value error, not just top-1 attention score.** The candidate must charge bound computation, mask/order construction, per-block indexing and all softmax/exponential operations. Precomputed centroids, radii and value maxima are reported as initialization cost separately (not charged per query); this is an optimistic upper bound on any benefit when the model reuses KV data across many queries.

## Frozen synthetic cases and classification

- NumPy float64, 1 BLAS thread, `D_key=D_value=64`, `N=1024`, 16 blocks ×64 keys; seeds `[9601,9602,9603]`. For each regime/seed create one `K,V` and 8 query vectors in fixed generator order. Values `V` are independent `N(0,1)` row vectors in BOTH regimes.
- `iid` negative control: all keys and all 8 queries independent `N(0,1)`.
- `clustered_aligned` deliberately favorable control: 16 independent `N(0,1)` key centroids, each of 64 keys is centroid plus independent `N(0,0.02)` noise; 8 query vectors `q=2.5*c_0 +N(0,0.1)`. Favorable aligned queries are NOT authentic model queries. Regime-specific generation may not draw on baseline predictions.
- Exactly `3 seeds × 2 regimes × 8 queries = 48` cases. Precompute all key/value block metadata once per seed/regime, record milliseconds. For each case warm both algorithms once, then run **7 alternating paired timings**: baseline is optimized dense `(K@q)/sqrt(D)`, exact stable softmax, then normalized weighted `V`; candidate is block upper-bound exploration with full charged runtime. Time medians include entire candidate and dense query computation.
- For all 48 cases record: median baseline/candidate ms, speedup, groups and key rows scored, output max-abs and relative-L2 error, whether a certificate terminated early, and observed certificate absolute limit. Require zero nonfinite values, `relative_L2<=1e-3` for **every** case, and zero exceeded certificates when compared with exact dense output (allow `1e-9` purely for floating-point audit of the claimed absolute inequality). Validate each true block maximum score is <= its computed inflated bound (allow `1e-9` audit rounding).
- Exploratory **NO-GO** unless **both** regimes have median measured end-to-end speedup >= **1.15×**, all cases within the frozen error limit, and all certificates provably valid. An aligned-only gain is not a positive screen. If qualifying, label `CONDITIONAL_CPU_FEASIBILITY_ONLY`. The screening cutoff is not a new FORGE acceptance threshold.
- No pretrained model, authentic NVIDIA GPU, real softmax kernel, TinyLlama output quality, first-use admission or production change is implied. Separately qualified authentic model/GPU evaluations with optimized kernels, held-out workloads and original frozen criteria are required before promotion.
- Source, CI identity and raw case JSON must be retained in the existing FORGE draft PR, including negative findings. No paid API, additional controller or concurrent queue, merge, accepted-ref mutation or promotion.

No hyperparameter, threshold or case may be altered after observing results; protocol changes require a distinct versioned screen.
