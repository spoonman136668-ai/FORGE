## Frozen tiny-state predictor and controls
All reservoir states are uint8 (exact 256-state bound), reset to seed state **17** at the start of every segment. For each observed char with alphabet index c (0..26):
* `chaos_state`: `(3*s*(255-s)//255 + 17*(c+1)) % 256`. A finite nonlinear logistic-like update, **not mathematical infinite precision chaos**, no gradient learning of recurrence.
* `linear_state`: `(37*s + (c+1)) % 256` (matched 8-bit state, matched training).
* `hash_state`: first byte of SHA256(`b"forge-acc67-u21-v1" + bytes([s,c])`) (matched 8-bit state, matched training, more computation).
* `ngram2`, `ngram4`: fitted conventional character count predictors using same FIT source and alphabet.

Each mode trains **one pass** of next-character conditional count tables (feature key = uint8 state or exact 2/4-char suffix), with add-one likelihood smoothing over 27 symbols and global FIT-frequency fallback for unseen states. State modes warm by processing the first four chars before first target, then step state with each *observed* target (teacher-forced) after prediction. No use of CHECK labels for training. No recurrent backprop, no pretrained LLM, no real autonomy/continual learning. Select DEV-best conventional/matched alternative from `ngram2`, `ngram4`, `linear_state`, `hash_state` by DEV exact token count (ties smaller deterministic JSON table bytes, then fixed order). Compare **frozen chaos_state** with this DEV-selected control on every CHECK window.
