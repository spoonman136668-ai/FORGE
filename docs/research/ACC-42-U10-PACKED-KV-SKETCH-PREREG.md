## Mechanistic question

Does a genuinely **bounded packed fingerprint/value sketch** preserve more usable exact value retrieval at a fixed 64-KiB logical state budget than competitive conventional fixed-size exact-key associative hash indexing **without compromising unknown-key integrity or consuming more full-process CPU**? A sketch whose 16-bit fingerprint matches a different key is a false-positive error, even when its returned value coincidentally matches; accuracy is not replaced with a likelihood score. This is a compiled Go data-path analogue with 64-bit keys/32-bit values, **not LLM KV cache attention**, language quality, semantic matching, neural model weights or original native AI acceleration.

## Frozen workload and full accounting

- Public deterministic `mix64`-generated independent 64-bit keys and values. Each independent episode: **8192 inserts** and **16384 lookup requests** (8192 from public inserted-key inventory and 8192 definitely absent keys carrying a disjoint top-bit domain). Distinct keys for positive puts have top bit clear; negative queries always top bit set; observations and schedules are public to *all* arms, **not** to the predictive model as answers. If a key is repeated, last-write-wins with a deterministic value based on both key and insertion index.
- Three independent source-free cohorts: **HOT** (2048-key write universe), **WIDE** (8192-key write universe), **CHURN** (16384-key universe with an update stream selecting keys across a broad space). Session workload seed identities **84101, 84103, 84107, 84109, 84111**, 16 freshly reset episodes per child with session-separated deterministic pseudo-random stream keyed by the trial seed. Same source stream, exact key sequence, values, oracle truth, operation order and budget on every arm. An independent exact unbounded Go `map[uint64]uint32` audit oracle is built from the same source **within the child**, and its CPU/RSS are charged to all modes equally. Do not pass oracle answers or unbounded identity dictionaries to the candidate.
- Each mode does one full episode **build then queries**, resetting all state and oracle between episodes. Source generation, audit truth, building, loading, queries, checksum, JSON reporting and all allocation are included in **whole-child** measured CPU, wall and physical peak RSS. The oracle, source and trial bookkeeping memory are explicitly not counted as sketch state, but remain charged to physical RSS in *every* mode. Report both, never confuse logical bytes with physical RSS.

## Arms and memory (the number 64 KiB is a fixed *logical state* cap)

1. **EXACT_SINGLE**: conventional 1024-bucket, 4-way exact 64-bit key / 32-bit value / 32-bit insertion-age packed table, 4096 slots × 16 bytes = exactly **65536 logical bytes**. One independent public key hash, most-recent replacement on equal key, otherwise first empty or oldest slot within one bucket.
2. **EXACT_TWO**: same 4096 ×16-byte full-key entries, two independent candidate buckets, exact key matching in both, deterministic least-age replacement across eight candidate slots. Strong exact equal-byte 2-choice baseline.
3. **SKETCH_TWO**: novel 2048 buckets ×4 packed slots = 8192 slots ×8 bytes = **65536 logical bytes**, each slot 16-bit fingerprint, 32-bit value and 16-bit age; candidate buckets hashed independently from the complete public key, two-choice least-age replacement. Query matches only tag and buckets, without storing or accessing hidden full keys. Detect/charge false positives against the *external audit oracle*. Tag zero is allowed; 0 age marks empty. Age counts 1..8192 inserts and cannot wrap during an episode. No oracle-assisted disambiguation or adaptive training.
4. **FULL_MAP**: standard unbounded exact Go map of observed pairs, diagnostic only. Map's physical RSS is measured, *not* counted as a 64-KiB bounded competitor, and may not be selected as the benchmark speed reference or declared a candidate victory.

All three bounded arms use one source-selected immutable 64-bit finalizer, same input stream, epoch reset, and no future lookup oracle. Eviction only on insert, not query, across all bounded arms. Every inserted key is allowed to overwrite its most recently stored exact or fingerprint match; collisions of tags may yield wrong return on exact key and must be counted.

## Metrics, repeatability, failures

- **Each native OS**: Go 1.25.5 compiled on GitHub-hosted `ubuntu-latest` and `windows-latest`. **Five paired cold children × 3 cohorts × 4 arms = 60 actual independent child workers per host**. Every child contains 16 separately initialized sessions. Alternating AB/BA order per seed block rotates SKETCH_TWO before and after the controls. Paired sessions never share a process. Record exact workflow source SHA, source-generator identity, all five raw samples and seed/order; no post-result subset selection.
- For each child report original-operation count, source SHA-256 for deterministic stream (must match all four arms and both OS), audit oracle digest, result trace, true-present count, correct exact value count, *false-positive absent-query count* and wrong-value count, exact state bytes, occupied slots, total updates/evictions and logical bytes per correct retrieval. Importantly **false positives on an already inserted key with wrong value are counted as wrong-value** separately and fail accuracy.
- Parent collects cold child `ProcessState.UserTime()+SystemTime()` (whole-child CPU seconds, including cold process startup) and spawn-to-exit wall seconds, with **peak physical process RSS bytes** from Linux `/proc/self/status VmHWM` or Windows `GetProcessMemoryInfo PeakWorkingSetSize`. Go `MemStats.Sys`, VM mapped size, and table's fixed 65536 bytes are not physical RSS proxies. CPU=0, RSS=0, source mismatch, incomplete children, failure to detect absent-key errors, digest mismatch, source drift or API unavailable -> **ACC42_U10_BLOCKED**; never impute zero or substitute parent Python time.
- Median accuracy and resource metrics are computed per cohort and OS from all **five** paired seeds, not worst-case handpicked individual trials. Cross-OS reconciliation compares source and audit identities, not absolute CPU seconds across machines.

## Frozen success / failure criterion

For an **all-cohort, both-OS limited *native Go engineering positive***, ALL conditions on Linux and Windows, separately for HOT, WIDE, CHURN, must hold:
- Valid source, proper last-write-wins oracle custody, zero wrong-value deliveries and **absent-key false-positive fraction <= 0.002** for SKETCH_TWO; on HOT candidate exact-value recall >= **0.98**.
- SKETCH_TWO per-cohort median exact-value recall >= the **larger** median recall of EXACT_SINGLE and EXACT_TWO **minus 0.01**, while its median **whole-child process CPU <= 0.90×** the **faster** median CPU of EXACT_SINGLE/EXACT_TWO (same arm's physical RSS used for any control memory comparison). A low-accuracy fast sketch never qualifies.
- Fixed packed logical table size **<=65536 bytes**, and candidate median peak OS RSS **<=1.10×** the fastest-CPU exact control's median RSS; all source/audit data charged identically. Any zero/unavailable CPU or RSS is **BLOCKED**.
- For each mode, output digests are deterministic per seed on each OS (cross-OS exact results expected for integer-only algorithm). Candidate can have different output trace than exact control, but all modes must see **identical input/source and independent oracle truth**.
- Even if these thresholds pass, this is only **bounded source-free native Go KV-like storage**, not a measured native Wingless/Yggdrasil model win or actual transformer KV-cache acceleration, task-level reasoning, long-horizon retention or scientific admission. No automatic promotion.
- If all measurements valid but any threshold fails: **U10_NO_GENERAL_VERIFIED_NATIVE_GO_RESOURCE_WIN**, with true per-cohort successes/failures and raw receipts preserved. Do not tune post hoc to win; only a separately preregistered future study could explore an alternate fingerprint width, memory budget or workload.
