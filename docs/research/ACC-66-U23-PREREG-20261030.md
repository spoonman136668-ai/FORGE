## Four trained predictors, exactly matched sources
* Conventional 1-, 2-, and 4-character count conditional predictors, with add-one categorical probability smoothing over 27 symbols and global FIT-frequency fallback on unseen context. Each trained by a **single forward pass** over FIT examples, one chosen via highest DEV exact-character accuracy (ties: lower serialized table bytes, then shorter context), and evaluated once on CHECK.
* Candidate `spectral_power_4`: for a four-character context, one-hot each of 27 alphabet symbols over positions 0..3. Compute complete 4-point DFT **power** (integer `F0`, `abs(F1)^2`, `abs(F2)^2`) per symbol, use the concatenated 81 integer feature vector as a count-conditional key, same global fallback/smoothing. One-pass FIT frequency table and single CHECK pass. Power omits phase; 4-point circular shifts have exactly identical features. This is a *bounded phase-discarding spectral candidate*, not all possible spectral language architectures.
* Exact phase-preserving DFT inverse test as a **representation-only control**. If phases are kept, original four-symbol order can be recovered, but this alone provides neither compression nor predictive advantage; do not label it as a separate tested faster model.

Report all FIT/DEV/CHECK source-window SHA256, global alphabet size, model key counts, deterministic serialized conditional-table bytes, forward-pass train+CHECK compute wall time (exclude downloading, preprocessing, validation, source startup), exact CHECK predicted token SHA, heldout accuracy, add-one smoothed negative log likelihood, unseen-context rates and adversarial four-character rotations with differing targets. Time via `perf_counter_ns`, warm each feature predictor once using a fixed neutral probe before timing (warmup never trains). **No real whole-LM latency, training FLOPs, physical RSS, CPU user/system, GPU or energy attribution**.
