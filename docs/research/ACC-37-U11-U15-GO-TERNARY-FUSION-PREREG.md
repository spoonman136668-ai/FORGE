## Native Go microkernel — no model or hardware claim
Two independently registered candidate kernels and one combination, all on **identical** actual tensor inputs: 128 output rows × 256 int16 input features, weights int8 strictly from `-1,0,+1`, identical bias and saturated/ReLU output semantics. Fixed 64 batches × eight independently cold data sessions per whole-worker process = **65,536 output dot products** and 16,777,216 input-weight dot-operations/worker, including synthetic input creation, result hashing, allocations and process startup in measured child CPU.

Four arms: **BASE** native Go integer multiply accumulation, then a separate bias/clamp pass; **TERNARY** conditional +/- accumulation, same separate bias/clamp; **FUSED** same native Go integer multiplication but integrate bias/clamp into the output loop; **BOTH** conditional +/- plus fused bias/clamp. The general integer-multiply baseline already sees weights -1/0/+1 so the compiler can optimize it. No intentionally weak Python loop or slower arbitrary-precision multiplier. No native model weights or tensors drawn from private native training.

Two frozen source-free workloads: `dense` with 15% zero weights and 85% balanced nonzeros; `sparse` with 82% zero weights, remaining balanced. Deterministic xorshift-derived original seeded input schedule independent of arm, eight sessions/worker; 64 batches per session, 128 output rows and 256 features. Per-event all results SHA-256 must match baseline on all four arms, on both OS. No approximate answer, dropped activation, numerical tolerance, new model or privileged oracle.
