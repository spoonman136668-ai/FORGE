## Genuine bounded hypothesis — finite tree-key memory
A hyperbolic Poincaré-disk coordinate encoding might retrieve hierarchy relationships more accurately than ordinary Euclidean distance on **the same two floating-point coordinates**, particularly deep trees. But geometry alone does not establish a self-learning semantic memory. Test balanced binary trees at **depth [4, 6, 8]** (31, 127, 511 nodes), with public structural/label seed **[26011, 26013, 26017]** per depth, giving 9 trees. Each tree is exactly defined by binary prefix paths; labels are deterministic SHA256 hex IDs from seed + path; no pretrained model or language learning. Embedding is **not learned**: parent/tree paths are used to create coordinates (oracle-assisted representation), and retrieval gold is generated independently from exact paths. No label or gold lookup during metric distance search.

Coordinates: each node at integer depth d has polar radius **r(d)=tanh(0.24*d)** in the open unit disk; angular coordinate is **2*pi*(leaf interval midpoint)/(2^depthMax)**, where each node's descendant-leaf interval is its binary-prefix range. Root is (0,0). Candidate retrievers use **the same (x,y)**:
* Poincaré hyperbolic disk distance `acosh(1 + 2*||u-v||²/((1-||u||²)(1-||v||²)))`, with robust domain clamps for floating error only.
* Raw Euclidean 2D distance `||u-v||` (same coordinates, same storage), no tuned embedding-specific variant.
* Exact parent-pointer/dictionary lookup (strong non-geometric conventional reference, 100% target expected with full path/parent pointer bytes charged).
* Frozen naive random-choice expected accuracy **1 / candidate count** as descriptive control only, not randomized cherry-picked outcome.

Target task: for a query non-root node, retrieve its **immediate parent** from **all other nodes** (exclude self, no depth or ancestor oracle filter). Score exact parent top-1. Hold out query nodes by deterministic SHA256(split-domain + seed + path) modulo 5: FIT residues 0..2, DEV residue 3, CHECK residue 4. **No hyperparameter tuning or candidate tuning from FIT/DEV**; report all splits separately but only CHECK determines decision. Verify split disjointness/coverage, report 100%-known parent reference and hash of CHECK IDs. To cap runtime fairly and sample deep trees without cherry-picking, use all CHECK nonroot nodes; **no limit**, pair same query candidates. Each OS measures each distance retrieval wall for a contiguous CHECK scan with `perf_counter_ns`; include coordinate distance computation and nearest-neighbor scan, exclude tree build and Python process startup; warm each distance mode once without evaluation-data training. Record per-tree exact top1 and query count, mean per-query latency, and 16-byte fixed binary64 coordinate payload per node (two doubles). Report Python dict/label/parent side bytes only as deterministic serialized JSON payload (not physical RSS); compare exact-pointer correctness and its payload, not speed as a fair search baseline (different access primitives).

Finite-memory negative: coordinates of 2 float64 values have at most 2^128 distinct raw bit-pairs, and storage of 16 bytes per node grows with node count. A fixed **16-byte record cannot uniquely represent an unbounded set of arbitrary independent IDs**, even if two coordinates permit infinitely fine real-number imagination. This is an abstract counting bound; no claims about actual trained parameter entropy or physical memory. Quantize each coordinate into signed 16-bit integer by `round(x*32767)` and record distinct coordinate keys and collisions per tree as empirical finite-precision diagnostic; do not label an absence of collisions as infinite memory.
