## Frozen design
- Same G62 pretokenized public exact-input cohort: six arrival-ordered requests, 16 greedy generated tokens/request. `high_locality=[0,0,0,0,1,1]`, `unique_only=[0,1,2,3,4,5]`, `thrash=[0,1,2,0,1,2]`. Request suffix uses original G55/G62 source strings. Identical output SHA and exact token equality per request.
- Two separate **CPU affinity/resource budgets** B=2 and B=3. On Linux, set actual process CPU affinity to exactly B eligible logical processors (verify and record). Keep torch intra/inter-op threads =1. All arms allowed at most B concurrent model-forward workers; record thread pool allocation, counts and CPU affinity. B=2 comparison: no-cache/serial 2 decoding workers versus overlapped 1 decoder+1 dedicated prefix producer. B=3 comparison: no-cache/serial 3 decoding workers versus overlapped 2 decoders+1 dedicated prefix producer. Production GPU and equal-power claims remain excluded.
- Freeze same causal G59 adaptive admission policy, exact prefix-token identities, cap 2 entries and 42,000,000 retained K/V tensor bytes. Never read future labels or outputs to determine cache admission. Scheduling uses arrival-order coordinator and enqueues decoding requests without artificial wave barriers; every arm receives identical arrival sequence. Prefills for serial arm are completed by coordinator before enqueue; for overlapped arm are submitted to a **single-flight dedicated producer** while decoding may run on distinct workers. Cache hits join the existing future; no duplicate producer per resident identity. All costs including admission/prefill/future wait/clone/eviction/decoder are counted from start through completion of all six requests.
- For B=2 and B=3, compare three arms: `no_cache`, `serialized_prefill`, `overlapped_singleflight`; three counterbalanced paired repetitions per cohort after untimed parity check and one warmup per arm; report per-trial whole-stream elapsed, process CPU, tokens/s, request latency p50/p95, prefill/worker time intervals, verified prefill-vs-unrelated decoder overlap, 10ms sampled RSS and exact retained-KV tensor bytes. Memory cap is retained tensors only; RSS sample is not exact peak.
- **No artificial sleep, spinning, or model slowdown to demonstrate overlap.** True concurrent execution is verified by timestamped overlapping intervals; do not require overlap for unique-only with zero prefills.

## Frozen screening rule
- Exact generation parity with original no-cache source and no retained KV over cap are mandatory for both CPU affinity budgets. All three cohorts and both resource budgets must be recorded (including negatives).
- Qualify an **equal-resource engineering screen** only if B=3 high-locality overlapped/no-cache median >=1.05x, B=3 high-locality overlapped/serialized >=1.05x, B=2 high-locality overlapped/no-cache >=1.00x, and B=3 unique-only overlapped/no-cache >=0.95x, plus at least one measured high-locality prefill/independent decoder interval overlap. If FAIL, preserve raw results and do not change thresholds or rename an unrelated speedup as acceptance.
- Compare actual worker allocations and observed overlap, not just thread count from user flags. Scheduler policy (non-wave versus G62 wave) and CPU host variability are confounds; this is a stronger resource-controlled screen, not independent scientific acceptance.
- Scientific/prod acceptance NOT GRANTED. Linux/Windows source CI must pass on the exact final SHA before claiming final source qualification. Only a distinct follow-on gate may address real serving stacks, multi-host holdout, GPU and peak memory.
