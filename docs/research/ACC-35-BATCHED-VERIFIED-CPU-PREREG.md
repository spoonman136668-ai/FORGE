## Prospective new ACC-35 design
- Reuse exact `research/acceleration/acc34_go_delta/isolated_core/core.go` frozen Go kernel (32 output nodes, 24 input bits, 96 iterations/node/event, hidden conjunctive cause), unchanged original Go module and original model trees. No redefinition of quality, task, candidate or intrinsic event cost.
- Every *new* **complete Go child worker** performs **32 independently reset** 4,096-event source-free sessions, one for each deterministic sequence seed `seed + k` for `k=0…31`. Each session begins with fresh zero public state, runs its own separate FIT dependency discovery for UNVERIFIED and VERIFIED, all own selected events, verified full checks, memory readings and exact rolling output checksum. Therefore **131,072 complete events per worker**, all import/startup/32×FIT/32×verification/checksum charged. This workload is intentionally **not identical to ACC34's one-session lifecycle**, so results must not be blended or described as exact replication; it addresses only inadequate Windows per-worker CPU time resolution.
- Same 2 scenarios BENIGN and HIDDEN_INTERACTION, same original five matched seed identities `91101, 91103, 91107, 91109, 91111`. One unmetered 32-session warmup per 4 arms per scenario, then five paired alternating full/verified AB-BA trials per scenario per OS, plus separate unsafe unverified and unavailable-information oracle worker on identical 32-session sequence seeds. **40 measured 32-session Go workers + eight warmup workers per OS**. All four arms use exact identical public events for each seed/round, output checksums for **all 32 individual sessions** must match FULL for VERIFIED and ORACLE, while UNVERIFIED must match benign and demonstrably diverge on at least one HIDDEN session; repaired causal interaction recorded from source results, not hardcoded. Fail with `ACC35_HIDDEN_SOURCE_FALSIFIER_LOST` if behavior does not hold.
- **CPU**: Go parent driver measures child total `os.ProcessState.UserTime()+SystemTime()` after exit (includes process start and Go worker 32 sessions), **nonzero** required on both Windows 2022 and Ubuntu 24.04; Windows zero CPU is **BLOCKED**, never interpreted as a benchmark negative. **Memory**: report `runtime.MemStats.Sys` runtime-owned bytes and `TotalAlloc`, not actual peak RSS nor GPU memory. Parent spawn-to-exit wall secondary. No power/energy numbers. Five raw paired CPU/Sys ratios per scenario and OS; medians from actual samples, no selective wins.
- **Engineering positive** only if both OS and both BENIGN/HIDDEN scenarios: VERIFIED checksum perfect, no delivered wrong result, hidden FIT miss detected and repaired, VERIFIED **median whole-child CPU ratio ≤0.90** versus FULL and VERIFIED Go `Sys` ratio **≤1.10**. Under-performing CPU means `ACC35_NO_TOTAL_VERIFIED_BULK_GO_CPU_WIN__NO_SCIENCE`, a valid negative, not a CI failure; if measurement clock remains zero or source parity breaks then `BLOCKED`.
- These trials are **native Go kernel experiments**, NOT actual Wingless native model, Yggdrasil native model, real LLM inference, causal generalization, neural training, verified energy, scientific improvement or any acceptance/promotion. Report every opposite, including faster unsafe/oracle arms and their missing information.
