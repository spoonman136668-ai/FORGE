## Frozen concurrent serving-control arms
- Authenticate source and data before inference. Restrict each trial to exactly **3 eligible Linux logical CPUs**, verify affinity and one torch intra/inter-op thread. Use a bounded **concurrent HTTP localhost** server with at most 3 in-flight request handlers; include HTTP client transport and thread scheduling in whole-stream end-to-end wall time. Server and model remain warmed; startup and downloaded weights are excluded but reported separately. Real network ingress outside localhost, TLS, load balancing, process isolation, autoscaling, and disk caching are NOT tested.
- `baseline_incremental`: handle each HTTP request in an independently scheduled max-3 worker pool, pretokenized exact input with manual incremental KV decoding; no cross-request prefix retention.
- `hf_generate`: same server/pool and concurrency; single-request HuggingFace `model.generate`, do_sample=False, 8 new tokens, per-request KV caching. This is a **reference serving library control**, not an independently optimized production engine.
- `shared_prefix`: same server/pool and incrementally cached decoder, cache the shared system prefix only when the exact-prefix identity is repeated; charge prefill, admission, future/copy and eviction; cap **2 entries / 42,000,000 retained KV bytes**. Unique-system control must demonstrate the no-reuse penalty; retain zero cross-request prefix KV on 0% reuse. The shared-prefix arm may observe only previous request prefixes, never future request identities, labels or outputs.
- Stronger optimized-serving comparison is **not** satisfied by either HuggingFace generate or this bounded localhost server. The G67 outcome may establish a limited library/HTTP engineering screen, but no scientific acceptance until an independent optimized inference stack is qualified.
- Start each cohort with clean prefix cache; warm model with *different* non-held-out G55 public prompts, not the selected instructions. Use 2 paired counterbalanced repetitions, alternating arm order, deterministic arrival batches of at most 3 simultaneous HTTP clients and fixed order within batches. All future-trials are blocked if correctness checks fail.
- Output: per-request exact GPT-2 generated token IDs + SHA; every arm exact parity to baseline on all 12 requests; measured end-to-end wall time including serialization and HTTP; per-request p50/max/p95 sampled latency and aggregated tokens/sec; process CPU; max retained K/V bytes and hit/miss/admission events; 10 ms sampled RSS explicitly **not** exact peak; full dependency/environment freeze, model, dataset and source hashes.
- Protect against serving deadlock, concurrent immutable cache mutation, header/content-size excess, request index out of range, poisoned traffic, memory cap breaches, false cache hits or output parity differences. HTTP server bound to **127.0.0.1** only, all handlers issue only frozen requests, no external binding or secret use.
