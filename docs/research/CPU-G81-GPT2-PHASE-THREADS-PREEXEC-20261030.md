## Hypothesis, technical candidate and controls

CPU prefill is dominated by original dense FP32 matrix calculations; supplying multiple intra-op CPU threads to prefill alone, then reducing to one for short incremental tokens, might improve total response latency without changing the model or its arithmetic dtype. PyTorch thread-pool changes may be expensive: **all changes and synchronization are timed** and included in candidate cost. Treat accuracy as *empirical identical original greedy tokens*, not bitwise hidden-state parity. No retraining/precision/masking/future token peek/multiple speculative outputheads.
