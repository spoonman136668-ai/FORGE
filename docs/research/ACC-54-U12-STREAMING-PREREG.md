# ACC-54 — prospective original U12 out-of-core parameter streaming

**Frozen before benchmark implementation or observation.** Original AC-08 30-candidate name register at `research/ac07_sourcefree/ac08_portfolio.py` Git blob `5126c860771fb024ccfc14c3f7ee8925edf29787` establishes one-based U12 = **out-of-core parameter streaming**. Existing ACC-34 research parent `45b5d8173538a566bf0f63a8e2ade2dedb6e6166`. This is a synthetic exact weight-access Go study, not a real trained-model inference or scientific first use.

**Hypothesis.** A bounded out-of-core chunk streamer with a 64-page cache can reduce process physical memory without sufficiently harming throughput versus strong in-memory, conventional memory-mapped, and direct file-access baselines. An apparently cheap RAM reduction that shifts bytes to uncharged storage and loses CPU performance is NOT a general win.

**Data and access:** Each native cold worker creates 64 MiB of deterministic uint64 parameters in a private temporary binary file using SplitMix64 seeded solely from its public input seed; exactly 16,384 4-KiB pages. After deterministic generation, evaluate 131,072 public indexed parameter requests, independent of method; all methods produce exactly the same uint64 answer and SHA256 digest, and the worker's independent deterministic direct-index oracle verifies every answer. Four workloads: SEQUENTIAL, HOTSET (256 recurrent pages), STRIDED (fixed stride with all pages visited), RANDOM (uniform 16,384 pages). Five original paired seeds [104101,104103,104107,104109,104111], one source/access sequence per seed/workload shared across four arms. Data generation, file writes and final cleanup included in whole-process CPU/wall; report process I/O read/write bytes and actual physical peak RSS. No data or answer oracle supplied to candidate.

**Arms:** RESIDENT read entire file in memory and index it; MMAP conventional OS memory-mapped page access; DIRECT_READ seek/read 8-byte parameter with conventional buffered file descriptor; STREAM64 candidate reads whole 4-KiB pages on demand into fixed 64-page LRU, validates bounds and does not keep the full 64-MiB parameter array. Distinct page-fault and cache hit/miss accounting, committed process logical resident state, exact output counts and data/access/output hashes. MMAP may require platform-specific implementation; if unavailable, **BLOCK**, never silently substitute another arm. Each arm's temp file is independent and destroyed after each test. No network or paid API.

5 seeds ×4 workloads ×4 arms = **80 genuine cold Go worker subprocesses per OS** (Go 1.25.5 Windows and Linux). Worker emits whole-child User+System CPU, elapsed wall, Linux VmHWM / Windows PeakWorkingSetSize actual physical peak RAM, source/access/output SHA and actual file I/O counters. Source, access and output parity across both OS mandatory. Include Go test/vet/build, original 36-negative portfolio unchanged, Git prereg identity and source blob hashes, independent 80/80 audit, raw Actions artifacts.

**Frozen restricted engineering positive:** candidate STREAM64 exact on every request AND in every workload on BOTH OS: median physical peak RSS <=0.50× RESIDENT; median whole-child CPU <=1.10× fastest conventional RESIDENT/MMAP/DIRECT_READ; wall <=1.20× fastest conventional; OS input bytes <=1.50× bytes read by conventional DIRECT_READ in same workload; bounded 64-page cache.
