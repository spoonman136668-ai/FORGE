## Question and source
Can an actual **native Go rank<=16 adaptive-cross-approximation (ACA)** matrix factorization of a public dense 128×128 float64 weight matrix reduce full-worker CPU and logical persistent matrix bytes **at comparable output accuracy** against exact conventional dense, blocked and sparse-CSR matrix-vector multiplication? Factorization fits **only the public dense weights**, not the hidden generating factors, and all its decomposition cost is charged to the measured worker. No oracle factor vectors, future outputs, tuned dimensions, saved full matrix as candidate state, paid library, GPU or model source modifications.

Five paired source seeds **94101, 94103, 94107, 94109, 94111**; 32 independent reset episodes per cold worker, seed namespace `0x55e97a2403bc819d`. Every episode independently generates a 128×128 matrix and 128 deterministic input vectors. Three cohorts:
- **RANK8** exactly constructed rank-eight with independent deterministic public matrix entries, no surviving pre-factor data in candidate; no added noise.
- **RANK24** exactly constructed rank-24, beyond fixed candidate rank capacity.
- **FULL_RANDOM** independent dense signed random entries (no low-rank promise).
All arms receive identical public matrix, input vectors, and order. Source input/matrix SHA256 and independent exact reference outputs checked without exposing labels to fitting. Contrasts are not selected after seeing outcomes.

## Frozen matched arms
- **DENSE** conventional exact float64 row-major dot-product matvec.
- **TILED** conventional exact blocked matvec with 16-column contiguous chunks, same original public weight values.
- **CSR** conventional sparse-CSR storage of exact nonzero matrix entries; charge index construction, column-index bytes and lookup, and allocate full source equally.
- **LOWRANK16** original U22 rank<=16 ACA using residual maximum pivot, reconstructing factors from the full public 128×128 matrix by fixed deterministic greedy extraction and stopping when residual is <=1e-12 of initial maximum. Persist only two fitted 128×rank float64 factors; no residual, original full matrix or undisclosed oracle inside the candidate *representation*. Matrix and truth data required for common-source validation are charged to all arms' peak physical RSS. Candidate matvec multiplies the compressed factors in two stages.

Each worker allocates a fresh public matrix, creates its selected representation once, applies all 128 source inputs, and compares each output to a separately generated exact original-matrix reference, with **reference evaluation charged to all four arms identically**; this is an intentionally conservative *whole-workload* test that may disfavor compression. Separately record inference-only CPU via monotonic timing (diagnostic; cannot substitute for whole-process CPU acceptance), 32 reset episodes, source and output digests, absolute squared errors, signal energy, factor rank, logical persistent bytes, Go process CPU/user/system and true OS physical peak resident working set. Cross-OS source and output trace SHA identities required for each arm (exact float results and IEEE finite checks). Differences vs baseline may be tolerance-scored, not falsely exact.

## Qualification and decision
Go 1.25.5, GitHub-hosted `ubuntu-latest` and `windows-latest`, **5 paired cold child processes × 3 cohorts × 4 arms = 60 actual independent children per OS**. Alternate AB/BA ordering by seed. Each child runs 32 reset episodes ×128 input vectors and complete reference validation; fit, source generation, exact comparisons, digest and reporting all charged. Full-child CPU measured by parent `ProcessState.UserTime()+SystemTime()`, wall measured parent spawn-to-exit, Linux `/proc/self/status VmHWM`, Windows `GetProcessMemoryInfo PeakWorkingSetSize`. Whole-worker CPU=0, RSS=0, error/digest/source mismatch, skipped tests, data/source alteration, incomplete 60 trials or nonfinite metrics => **ACC45_U22_BLOCKED**.

The acceptance gate is intentionally demanding. To count a **restricted native Go engineering win**, ALL of these must hold in **all three cohorts and both operating systems**: 
1. Candidate normalized root-mean-square error (total output error sum / total exact signal sum, square root) <= **0.01**, and max absolute normalized error finite, with no secret input, approximation-label leak or hidden rank factors.
2. Whole-process CPU median LOWRANK16 <= **0.90×** the fastest conventional median CPU among DENSE/TILED/CSR; physical peak RSS <= **1.10×** that exact fastest-CPU conventional control. A diagnostic inference-only benefit is not sufficient to override failed full-worker acceptance.
3. Candidate persistent factors <= **0.50×** DENSE persistent weight bytes and each exact conventional arm's source equality, fully charged fit and verification, with cross-OS source/truth/output parity. No native-model integration from a source-free synthetic trial.

If accurate and complete but any criterion fails: **`U22_NO_GENERAL_VERIFIED_NATIVE_GO_RESOURCE_WIN`**; report per-cohort conditional advantages and failures without cherry-picking. If every criterion passes: **`U22_RESTRICTED_NATIVE_GO_ENGINEERING_POSITIVE_ONLY`**, still not Wingless/Yggdrasil model acceleration, TT tensor claim, scientific first-use or FORGE deployment. No retroactive threshold changes; distinct follow-up requires new prereg.
