## Controlled experimental design
- `unique_system`: 12 distinct long system prefixes generated by original G70 prefix construction, zero cache hits/admissions. **Negative control** (no spurious caching).
- `repeated_system`: 12 requests use identical authentic original G55 `PREFIX`, plus 12 distinct question suffixes. **Positive control** (at least one admission/hit, first-use-before-cache admission).
- Four independent localhost HTTP arms with **identical** 12 requests/order and 3 active clients per wave:
  1. `baseline_incremental` — original manual PyTorch token-by-token incremental decode, no cross-request cache;
  2. `hf_generate` — original PyTorch HuggingFace generation, no cross-request cache, independent library comparator;
  3. `shared_prefix_deepcopy` — **unchanged** original G70 `PrefixStore`, cap exactly 2 retained entries and 42,000,000 bytes, original per-request `copy.deepcopy(cached)`;
  4. `shared_prefix_readonly` — same PrefixStore admission, eviction, concurrency bounds and input model; per-request `past_key_values` references shared cached tensor values without deep-copy, no in-place writes and no unsafe reuse of mutable request-specific state.
- **Critical alias safety:** before benchmark, verify all tensors in an admitted frozen prefix KV have identical dtype/shape/strides/storage and byte digests before, during and after two concurrent continuations. No tensor of the shared prefix may be mutated; all generation branches must have exactly 8 identical token IDs against uncached manual and HF reference. Additional negative mutation fixture must be detected and fail closed. Full immutability fingerprints and offset/time costs run **outside timed HTTP measurements** (report their wall-time separately); check again after all timed trials. Unchanged original deep-copy arm is strict comparator.
- One untimed public-text warmup per arm (not heldout), then **3 paired counterbalanced order rotations** / cohort: 2 cohorts x 4 arms x 3 repeats x 12 requests = **288 timed HTTP responses**. Rotate first arm each repetition; reverse odd repetition. No selective runs.
- 3 eligible logical CPU cores pinned using `psutil.cpu_affinity`; one PyTorch intra and interop thread; same thread pool, HTTP handlers, tokenization, request arrival waves, TCP localhost queue, model and resource limits in all arms; no GPU, paid API, model service, controller or production queue. Record every whole-cohort request wall, sample latency p50/p95, per-trial and per-client token digests, process CPU, sampled RSS 10 ms (approximate; not physical peak), cache hit/admission/eviction/byte metrics, model startup and metadata.
- All model/dataset/source verification and frozen disjointness checks must pass before benchmark. Do not use answer-caching, replay of output tokens, future requests or matching by generated answer.
