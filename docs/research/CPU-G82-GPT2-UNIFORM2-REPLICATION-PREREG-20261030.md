## Frozen controls and method
- **Three** real original full-request arms with a single model, identical input masks, cached original forwards and FP32 weights:
  1. `uniform1` PyTorch intraop thread count 1 for prefill and cached decode — established original baseline.
  2. `uniform3` thread count 3 — native multicore strong alternative.
  3. `uniform2` thread count **2 both phases**, the preselected G81 control whose repeatability is being tested.
- All arms pinned to the same exact **3 logical CPUs**, inter-op=1, all `torch.set_num_threads(N)` calls **charged inside their own timed full request**. No explicit prefill/decode phase switch; no extra CPU core for selected arm. All same G81 original mask, logits, independent fresh KV cache and Python token output. Original model only; test **entire request** (prefill+8 tokens+allocations), not head-only or HTTP throughput.
- Three public nonheldout warmups per arm, *untimed* independent uniform1 original parity reference for each human prompt. Then 12 requests × **5** rotated/reversed arm-order repetitions × 3 arms = **180 original timed full eight-token responses and 1440 original generated tokens**. Each must produce exactly the same original eight greedy token IDs as uniform1 and other arms; no skipped mismatch or changed weights. No dynamic selection after seeing test data. Record each response's wall ns, process CPU ns, sampled RSS (not physical peak), input/output hashes, per-arm median and nearest-rank p95, exact affinity/thread budget, original host/environment identity; paired differences and p95. Carry source SHA and prereg SHA in artifact. Never call or use external service/network as a latency baseline.
