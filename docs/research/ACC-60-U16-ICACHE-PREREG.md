# ACC-60 — original U16 compiled weights in instruction cache: prospective native qualification

**Frozen before implementation.** Original source `research/ac07_sourcefree/ac08_portfolio.py`, Git blob `5126c860771fb024ccfc14c3f7ee8925edf29787`, one-based hypothesis U16 **"compiled weights in instruction cache."** Research base `45b5d8173538a566bf0f63a8e2ade2dedb6e6166`. This is not a claim of actual instruction-cache residence; validate that separately using hardware counters if available and authorized. General CPU-only timing cannot establish hardware instruction-cache attribution.

**Question.** Does native generated Go executable code embedding a fixed quantized weight matrix outperform a conventional read-only flat array and a blocked tiled layout for exactly the same linear inference, without error or undue executable size and OS resident-memory costs? Exclude reflection, runtime Go compilation, model training, GPU, paid APIs, and hidden precomputation of input answers.

**Deterministic input.** Matrices with dimensions 16×16, 64×64, 128×128, 256×256 (rows × columns), int8 weights in [-8,7], generated from public `splitmix64` with seeds 116101/116103/116107/116109/116111. Each child cold process computes 4096 deterministic int8 input vectors and exact signed int64 dot-product outputs. SHA-256 all weights, inputs and complete outputs, independently recompute reference answers. No overflow (maximum 256×8×8). Three arms: ARRAY (row-major read-only []int8); TILED (8×8 blocked layout, no special answers); COMPILED (the SAME scalar arithmetic with literal weight constants embedded in generated static Go source, no runtime table read). Generated code size must be recorded from built binary; all source generation deterministic and Git-pinned before benchmark.

**Native execution:** 4 matrix regimes × 5 seeds × 3 arms = **60 independent cold child processes per OS**. Three alternating full-workload repetitions per child (same inputs) to obtain real CPU with no unrelated timing guards; preregister repetitions before observing. Each native child records whole-process User+System CPU and wall, physical OS peak RSS, binary size, number of outputs, output SHA, memory residency, and arithmetic exactness. Measure platform-specific binary sizes separately. Audit original 36 original research negatives, source identity, Go test/vet/build and all 60 independent source/output parity checks for Linux and Windows. If CPU reports zero, fail and preregister a separate amendment before increasing only true inference repetitions; never fill measured CPU with fabricated values.

**Positive acceptance:** COMPILED must achieve exactly matching all predictions and source/output digests for every seed and regime on both OS, median full-cold-process CPU <=0.85× fastest conventional per regime, peak RSS <=1.10× fastest conventional, total on-disk executable size <=1.25× ARRAY (same OS), and no regime accuracy regression. Both OS all cohorts must meet criteria. `U16_RESTRICTED_SYNTHETIC_GO_CODEGEN_POSITIVE_ONLY` is bounded to this tested inference and does not establish instruction-cache mechanism without hardware counters. Otherwise, if the experiment and audits are valid, `U16_NO_GENERAL_VERIFIED_NATIVE_GO_RESOURCE_WIN`; incomplete identities/CPU/RSS/correctness/controls => `ACC60_U16_BLOCKED`. Do not permit a positive for measured speed attributable only to omitted read-only data, missing code paths, or per-arm different work.
