# Private scientific archive — source-only qualification boundary

This public package implements **offline write-once FORGE scientific record storage**. It does not embed private experiment results, connect to a runner, or operate a controller.

## Local storage lifecycle

1. Choose a new **absolute path ending in `forge-research-archive`**, outside the CKB, KTRADE and Mind-Palace installations. `Initialize(path)` refuses existing directories and creates the dedicated marker and private `records/` and `originals/` directories. This API is not called by any automatic workflow.
2. `SaveOriginal(exactBytes)` places an immutable, content-addressed original evidence bundle (up to 8 MiB per bundle). This includes the **original** stdout/stderr/exit envelope generated by a future separately qualified collector—not reconstructed summaries or redacted replacements.
3. `AppendEvent(event)` validates the full pre-existing original journal, scientific transition, source/preregistration/cohort identity and consumed-cohort uniqueness before creating exactly one write-once sequential record with `O_EXCL`. Terminal/review/archive entries require their referenced original bytes to exist and hash correctly first.
4. `Open(path)`, `Load()` and `ReadOriginal(sha)` independently reject tampering, missing entries, holes, symlinks, corrupted evidence, path redirection and duplicate/replayed scientific starts. Tests use temporary synthetic fixtures only.

## Recovery and limits

This is an **early durable-file primitive, NOT yet a production-ready crash-recoverable FSA store**. File contents are synced and each new filename uses exclusive creation; where supported directory metadata is synced. Windows directory sync may not be available. If a process dies mid-write, a partial final record can remain and **blocks all further writes**. It must not be silently truncated, deleted, retried or inferred to be an authorized experiment. Reconciliation of an uncertain scientific run is a separately qualified FSA procedure.

A successful hash validates continuity, **not authenticity** of external signatures or scientific claims. **Deleting a complete trailing record can still leave an internally valid hash chain.** The `VerifyTrustedHead(sequence, sha256)` check explicitly detects this only when supplied a separately authenticated, monotonic FSA checkpoint; never trust a high-water value computed from the same local files. The current `AppendEvent` API does not enforce that external witness and therefore is **not an authorized production append path**. No process may claim exactly-once scientific execution from the file store alone. External FSA authorization and original-start receipts remain mandatory. Multi-file atomic transactions, authenticated FSA receipt validation, stable retention/backup, cross-volume recovery and partial-write repair require additional engineering and independent qualification.

## Hard resource and execution isolation

- The archive must never be placed under an existing CKB, KTRADE, research write-proxy or Mind-Palace controller directory.
- No FORGE code in this package launches processes, starts experiments, dispatches actions, writes broker/accepted refs or modifies external queues.
- GitHub Actions runs unit tests against generated temporary fixtures on GitHub-hosted Linux/Windows only; no private source or sealed experiment evidence enters the public repository.
- Mind-Palace documentation candidates remain **review-required, not automatically ingested**. Only independently reviewed or archived compact finding metadata may enter a future authorized private checkpoint path.
