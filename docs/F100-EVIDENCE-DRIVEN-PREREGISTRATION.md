# F100 — Frozen successor-development hypotheses from authentic negative outcomes

F100 continues **FORGE-native autonomy engineering** from F99's independently reaggregated historical Wingless W-F10 and Yggdrasil Y-F9 development negatives. It does not invoke an autonomous GPT model, Codex, ChatGPT Work or a paid inference API.

## Order of events

The exact preregistration `reference/research-intake/f100-frozen-successor-contract.json` was written in Git commit `92a29e81acc5018448f45bf7b2a52cec0cf77d10`, **before** any F100 verifier, test or execution code was committed. Its parent is pinned to F99 commit `4218c64f310c59b3a9124ec309d727475e6f2bf3` and the frozen historical negative manifest Git blob `a280814e324d80bcc2590bbab939446180683e45`. Historical DEV negatives have not become new independently accepted scientific results.

F100 freezes four mechanism families in two independent lanes:

| Lane | Candidate | Distinguishing falsifiable hypothesis |
|---|---|---|
| Wingless | W100-C1 | Depth-conditioned learned relational state and query head change answers when requested depth changes |
| Wingless | W100-C2 | Learned, bounded expected-information-value observation gate chooses different observations for different depth requests |
| Yggdrasil | Y100-C1 | Learned typed-role embeddings and an ordered relation composer respond correctly to role swaps |
| Yggdrasil | Y100-C2 | Learned variable-slot binding preserves renaming invariance and rejects incompatible relation-role bindings |

Each lane retains its original frozen learned baseline, size-matched information-ablated baseline, randomly permuted input ablation, always-yes shortcut and a powerful coded oracle **only as a control**. Candidate source code may not embed the coded oracle's algorithm and then claim it has been learned.

## Independent DEV screening

A separately frozen set of **three 16-seed public-development blocks per lane** excludes both historical W-F10 and Y-F9 source seeds. Seed identity, stratification, sample cap, up to 128 trainable parameters, up to 100 optimizer updates, paired counterfactual primary metric, worst-group metrics, compute budget and development-only pass/fail thresholds are frozen before code. Every candidate must be screened. Best-candidate cherry-picking, post-result edits and protected cohort reuse are disallowed.

The thresholds are **planning criteria**, not reported achieved results. The preregistration contains *no* learned experimental result, source implementation or new scientific original.

## Source and qualification

`nativeevidence/f100_frozen_successors.py` verifies exact previous Git source blob, row-derived negative records, four novel candidate identities, distinct falsifiable mechanisms, new frozen public DEV seeds, strong controls, budget and outcome gates. `nativeevidence/test_f100_frozen_successors.py` tries adversarial substitutions: forged positive findings, changed parent digest, missing candidates, repeated IDs, oracle leakage, removed controls, post-result retuning, original seed reuse, excessive budgets, malformed input and unauthorized first-use/science/model promotion.

The **existing** GitHub-native six-hour FORGE synthetic-cycle workflow runs these checks on both Ubuntu and Windows, emits a source-bound, checksum-backed preregistration proof, and leaves F98/F99's optional historical source observer independently quarantinable. There is no new runner, controller, API call or second scheduler.

## Safety and actual next research work

F100 is a **source-only preregistration and qualification gate**, not a demonstration of cognitive generalization or unattended hypothesis invention. Once F99 is merged and F100's exact-head checks are accepted, the appropriate next development gate is to implement the competing learned models in isolated research branches, run *public development-only* frozen cohorts with full controls, and keep scientific first-use unauthorized until independently verified permission and new-source custody exist.

No CKB-plane integration, no automatic Wingless/Yggdrasil run dispatch, no accepted-reference edits and no optimizer promotion.
