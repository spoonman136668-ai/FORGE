## Exact current history, without a stale checkpoint

The old V33 proof remains unchanged and must still verify at its original
sequence/hash. New schema `forge.f139.source-transition.v29` accepts only that
genuine V33/B8 predecessor, once, under the original owner mutex. At the idle
handoff it binds the actual current sequence/head, full ordered event prefix,
every historical terminal task and negative, the original V33 seal, all spent
publication counters, the compiler binary/toolchain and generation mechanism.
The proof is recomputed in the same SQLite transaction before any source update.
Stale proofs fail; growing counters are not reset. All eight old external-model
attempts remain spent and no external inference is enabled. Unacknowledged
publications, active/READY work, missing original custody or a changed owner
fail closed. Cold reads retain all historical exact checks.

## One original owner and one current release route

The existing V33 installer is restricted to its original B8 release ref. Only
the V34 successor receives new immutable `f139-owner-release-<exact SHA>`
creation events. It uses the same qualified runner, Windows SID, task, action,
poll interval, DPAPI handling, SQLite, release mutex and no-bypass ref rules.
There is no new controller, scheduler, task, source queue or retry loop.

After exact hosted release qualification and immutable protected-source checks,
the installer makes one nonblocking acquisition of the original SQLite lock's
Windows byte range. A busy tick rejects the handoff before task/policy mutation.
While holding that lock it disables/stops the existing sleeping owner and
verifies child-process absence. This prevents stopping a tick in a publication
or dispatch. The lock is released before the already-qualified maintenance CLI
obtains the original mutex for backup/rehearsal/transition work.

The existing cold backup includes the database, original negative archives,
provider archives/manifests and old generation executable. All copies are
hash-checked. A copied-original rehearsal commits the proposed source and native
activation, invokes the actual qualified typed generator without publication or
worker dispatch, and cold-reopens. The real original is updated only if source,
owner, policy, binary and original head still match that rehearsal.

The exact old policy is paused only after quiescence and verified idle backup.
Before any possible source mutation, failures restore that policy only when its
body still equals the leased paused body; conflicts hold safely. After possible
source mutation, failures preserve the original disabled/quiescent hold. They
never guess that an ambiguous source transition can be retried or replayed.

the exact immutable release ref can enter installation after qualification.
