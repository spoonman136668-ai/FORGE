## New ability

F106 automatically performed one preimplemented new-condition evaluation from F105 decisions. F107 adds real **machine-generated executable structural alternatives**, not only another prewritten experiment or parameter tweak. It consumes the actual source-bound F106 report and checksum from this same GitHub Actions run, validates its supported next-direction advice, then composes typed operator programs using a grammar frozen before implementation. It never generates arbitrary Python source or invokes an LLM.

Each candidate comprises a different combination of *computational operators*; the generated programs are executed using a safe fixed interpreter. Wingless varies query-attention sources, one/two/four-observation aggregation, and readout. Yggdrasil varies slot-preserving versus node-pooled state, message aggregation (sum/max/mean), and learned versus relative readout. The unchanged existing F104/F103 small trainable models supply frozen fitted parameters, trained for their original 100 steps using **only the original F104/F103 parent training blocks**. Candidate program mutation changes the **computation/dataflow**, not its learned weights, training split or protected scientific authority.

The search budget is up to 18 distinct programs per lane; a program changing only the final threshold/readout from the parent is excluded as insufficiently new. Each carries a stable hash of its typed AST, structural family, cost and source-bound generation lineage. Every candidate, including failures and unselected variants, is archived.

## Nonleaking controlled screen

F107 freezes new public-development seed blocks before code implementation: Wingless train 64800–64815 and diagnostic 64832–64847; Yggdrasil train 64900–64915 and diagnostic 64932–64947, three instances per seed (48 training and 48 diagnostic counterfactual pairs per lane). Neither cohort reuses the previous F103/F104/F106 blocks. The coded oracle validates generated labels as a strong external control; it is never used by the executable candidate.

All generated mechanisms are screened on **new public training cases only**. A deterministic Pareto filter retains nondominated score/cost variants and selects exactly one finalist per lane, breaking ties by lowest cost and AST hash. The **diagnostic block is evaluated only after selection**, against the finalist, unchanged parent, independently trained blind control and coded oracle. A positive/negative outcome always emits full test metrics and proposed next challenges; negative data are preserved, not retuned away or treated as a CI failure. Authenticated source mismatch, missing controls, malformed programs or altered protocol *are* CI failures.

## Meaning and limits

This stage can automatically explore a **fixed but compositional structural mechanism space** with actual executable alternatives, bounded public data and unattended train-only selection. This is a measurable advance over manually naming each successor mechanism. The search grammar and challenge generators are still human-specified; it has not independently invented an unrestricted new scientific hypothesis, trained a novel free-form model or demonstrated sustained scientific self-improvement. Toy development performance does not imply independently new-domain generalization.

It is not a protected original experiment, accepted scientific result, optimizer promotion, direct Wingless/Yggdrasil code mutation or GPT inference. The ChatGPT web client remains an advisory interface; the existing GitHub runner executes fixed non-privileged public development.
