# FORGE R6C-P1 — operator-ready read-only remote FSA probe

**Source-only deployment preparation**. This stage provides an executable, bounded observation client, not a listener, physical trust service, provisioning API, signer, or scientific authority.

## What changed

- `fsaremote.Client.Probe(ctx)` makes **five GET requests only** through the existing independently TLS-pinned authority and witness client: authority head + witness signed high-water, independently returned archive binding, then head + high-water again. It fails closed on transient outage, invalid signed witness, unknown archive binding, conflicting head/revision/digest, TLS pinning failure or identity change. **There is no POST, CAS, self-repair, replay, or loop.**
- `cmd/fsa-probe` accepts `-config /absolute/path/to/probe.json`. The JSON contains **only operator-provided immutable trust pins and absolute local certificate/CA/private-key file paths**. Key material is loaded into memory from files with an actual regular-file check; it is never embedded in the program, stored in GitHub, echoed into output, or generated by FORGE.
- The CLI emits one JSON observation on success, or a generic failure code without path, TLS identity, private key, signer or server details. Every observation explicitly contains `physical_independence_verified=false`, `independent_floor_verified=false`, `scientific_accepted=false`, and `execution_authorized=false`.
- Adversarial tests use real TLS 1.3 mutual-authenticated local HTTP test peers and signed Ed25519 high-water statements: valid read, in-flight change, missing binding, witness outage, canceled context, no CAS POST and no output authority. These tests **do not** demonstrate separate hosts, durable independent floor, actual power failure or real deployment.

## Configuration format

Store a locally generated operator-owned JSON file (do not commit it), for example:

```json
{
  "schema": "forge.fsa.remote-readonly-probe-config.v1",
  "archive_id": "64_lowercase_hex_from_external_pin",
  "key_id": "operator-approved-id",
  "authority_public_key_hex": "64_lowercase_hex_from_external_pin",
  "authority_epoch": 1,
  "binding_sha256": "64_lowercase_hex_from_external_pin",
  "witness_public_key_hex": "64_lowercase_hex_from_external_pin",
  "minimum_revision": 1,
  "authority": {
    "url": "https://real-authority.example:8443",
    "trusted_ca_file": "/secure/authority-ca.pem",
    "client_cert_file": "/secure/authority-client.pem",
    "client_key_file": "/secure/authority-client.key",
    "server_spki_sha256": "64_lowercase_hex_from_external_pin"
  },
  "witness": {
    "url": "https://real-witness.example:8443",
    "trusted_ca_file": "/secure/witness-ca.pem",
    "client_cert_file": "/secure/witness-client.pem",
    "client_key_file": "/secure/witness-client.key",
    "server_spki_sha256": "64_lowercase_hex_from_external_pin"
  }
}
```

The placeholder strings are **not valid pins**; copy no test or example private keys. Use genuine separately authenticated operator-issued values and private key storage. Paths differ by OS; Windows requires absolute native paths. Both roots, server SPKI hashes, client certificate identities, endpoint URLs, authority and witness Ed25519 keys must be distinct. The CLI verifies structural separation but cannot verify actual independent ownership.

Build without deploying: `go build ./cmd/fsa-probe`; test: `go test ./fsaremote ./cmd/fsa-probe`. The public CI also runs Go regression, race on Linux, vet and build plus native Windows Go verification. This is a safe *source* qualification only.

## Gate before any actual off-host test

1. Three independently governed, geographically/power/control-plane appropriate **persistent** authority, witness and monotonic floor failure domains must be provisioned under existing operator/cloud authorization, with independently verified identities and ownership.
2. The authority and witness must already implement read-only `/v1/fsa/anchor`, `/v1/fsa/binding` and `/v1/fsa/highwater` behind real TLS 1.3 mutual-authenticated endpoints. The floor must separately prove protected monotonicity. **This probe cannot validate the floor**.
3. From an independent observer host, run the probe against *actual* endpoints with independently pinned certs and CKB-independent FORGE keys, capture authenticated network traces outside the tested failure domains, and compare immutable high-water before/during/after **separately authorized sandbox faults**.
4. Do not claim R6B physical pass or FORGE acceptance until the existing [physical evidence gate](https://github.com/spoonman136668-ai/FORGE/issues/20) and independent audit are satisfied. Do not install this probe as an unattended scheduler, production service, secret exporter, or scientific authority.

**Boundary:** No FORGE draft merged or activated by source qualification. No new infrastructure charges, deployments, secrets, research execution, accepted-ref changes, or KTRADE action. Existing scientific controller continues unaffected.
