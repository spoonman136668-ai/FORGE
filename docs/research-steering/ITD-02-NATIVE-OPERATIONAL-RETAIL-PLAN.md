# ITD-02 — Operational native learners on ordinary retail PCs

**Status:** Owner-directed *implementation plan / engineering gates*, 2026-10-27. **Not a new research program, model architecture, experiment admission, controller, scheduler, protected first-use grant, or claim of consumer readiness.** This implements the existing [ITD-02 charter](https://github.com/spoonman136668-ai/FORGE/issues/857) and the unchanged Wingless/Yggdrasil North Stars.

## Plain-English objective

Get **two independently developed native AI systems** running on an ordinary new Windows computer. Each must be able to observe an eligible environment, choose its own actions, receive actual consequences, learn with its own non-transformer/non-next-token mechanism, preserve what it learns, resume after restart, and eventually improve on unfamiliar situations without a human or language model instructing each move. Keep both affordable in CPU, RAM, power and storage.

**Operational self-training is NOT** autonomous GitHub source editing, FORGE issue generation, a favorable authored fixture, a CI checkmark, a simulation with hidden oracle observations, or evidence of generalized intelligence. Separate working software from independent scientific acceptance.

## Hard environment contract (per architecture)

The external source owner alone returns `reset -> public_observation` and `step(selected_legal_action) -> (next_public_observation, public_reward, terminal/truncated)`, with a source event identifier and original source/role/custody metadata stored **outside learner input**. No hidden map, source state, task ID, seed, goal oracle, evaluator answer or future outcome may enter either learner. The native model chooses each action; its own update rule changes learned state. The source owner executes and measures an actual effect. A protected-origin episode has its own FSA authorization; public development cannot be repackaged as protected science.

A source step may occur before a process crash or network failure. Its result is then **uncertain** until the original source owner establishes exact custody; the same action MUST NOT be replayed blindly. Checkpoint only at verified commit points; retain frozen original checkpoint separately and version/hash the new learned state. Training may stop, but must not forge successful termination. Use a local source-owned durable journal if mid-episode resumption is needed; otherwise restart only at a verified episode boundary, explicitly discarding/retaining partial data per preregistered policy.

For Yggdrasil, keep local neighborhood messaging and actual learned-cell updates. For Wingless, keep original Go R5/R8 and selected feedback routing. A shared *wire convention* is allowed; a shared central policy, privileged replay service or Python/transformer replacement is not.

## Retail acceptance matrix — target tiers, not proven support

| Tier | Hardware to actually test | Required experience |
| --- | --- | --- |
| **Entry retail (target)** | 64-bit Windows 11, CPU-only (e.g., four logical cores), 8 GB system RAM, integrated graphics | usable install/inference and bounded local learning without an expensive GPU; no forced internet |
| **Typical retail** | Windows 11, 16 GB RAM, ordinary laptop/desktop CPU; GPU optional | practical interactive use alongside everyday desktop activity |
| **Development comparator** | Retail gaming laptop, including RTX 4070 class | measure acceleration and peak load, but **not** silently establish the minimum hardware |

For each tier measure **cold install and startup; median/p95 action latency; training interactions/sec; checkpoint/restart correctness and size; total resident/peak process-tree RAM and optional VRAM; disk growth per 1,000 interactions; CPU use, thermals and energy when sensors provide trustworthy data; whole-process overhead; sleep/pause/resume behavior; background responsiveness; and wall-clock cost**. Record sensor-unavailable fields as unknown, not zero. Define numerical budgets *before* using comparative results; no retroactive relaxing thresholds. A hosted CI VM is a portability signal, **not** evidence of retail-PC performance. No benchmark advantage counts if it depends on unreported cloud/training cost.

Initial device matrix is an **acceptance target**, not a promise that 8 GB is presently enough. If entry tier is infeasible, publish the precise measured blocker and optimize; do not assume an RTX 4070 is required.
