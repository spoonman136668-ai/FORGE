# FORGE Dream-RSI R10 — two-stage FSA wake/authorize protocol

**Status: source-only inactive integration, no FSA provider, no dispatch, no scientific execution.**

## Architectural defect repaired

FORGE R9 binds an independently issued work grant to the exact **GitHub Actions run ID**, first attempt, source SHA, tree, Wingless/Yggdrasil lane and consumed first-use evidence. An operator or FSA issuing a grant *before* the workflow starts cannot know the future GitHub Actions run ID. Without an explicit two-stage protocol, the seemingly complete grant path deadlocks or is tempted to omit critical run identity.

R10 establishes a **FSA prewake intent → GitHub run claim → independent FSA run-bound lease** contract. It does not assume the missing FSA service exists.

**Stage 1: FSA prewake, no science.** The separately controlled FSA signs a domain-separated intent over the exact repository, future scientific-workflow path, source Git commit and tree, frozen preregistration, experiment/cohort/qualifier, authority epoch and archive ID, resource ceiling and a unique independently controlled correlation digest. **The run ID is intentionally absent.** R10 requires an externally pinned complete intent SHA and an FSA prewake public key distinct from both the prospective dispatch-lease key and independent FSA archive-head key. A hosted GitHub workflow may wake on this limited intent, but cannot begin any original or consume a scientific cohort because of it.

**Stage 2: run-specific FSA lease after GitHub assigns the ID.** The hosted job returns a run claim containing source, tree, lane, correlation, repository/workflow, run ID and attempt 1. Its SHA differs for different run IDs; it is a **claim** and not externally attested GitHub identity by itself. The independent FSA must authenticate GitHub's actual run claim (e.g., independently validate the permitted GitHub OIDC claim set), recheck preregistered eligibility, scientific source, first-use evidence and cost budget, then atomically consume a protected, cohort- and run-scoped dispatch lease in FSA-controlled monotonic storage. Only after that independent transaction may the FSA return a separately signed lease tightly binding the exact prewake SHA, claim SHA, run ID, cohort, grant SHA, external dispatch high-water and consumption witness. The grant signing key and archive-head key must be distinct from the prewake key.

`hostedwake.ObserveWake` and `hostedwake.VerifyLease` cryptographically verify these structures and enforce role/source/run/attempt/lineage constraints. A valid signed **claim** alone does not attest independently verified GitHub identity, real protected lease consumption, physical key custody or a live FSA. Therefore their result is explicitly `OBSERVED_RUN_ONLY_NO_FSA_DISPATCH` or `SIGNED_LEASE_CLAIM_REVIEWED_NO_EXECUTION`, with all scientific execution/authority/physical trust flags FALSE. This is a contract that an independent FSA can implement; it **does not** convert test-owned signers into scientific acceptance.

## Future automatic cross-run transition

The independent FSA should be the only entity that calls **a separately scoped `workflow_dispatch` or `repository_dispatch`** for the pinned scientific workflow, after committing its prewake intent. GitHub Actions typically suppresses ordinary workflow triggers generated by its default GITHUB_TOKEN; dispatch events are explicit exceptions, but require an appropriately installed default-branch workflow and scoped credentials. A hosted worker cannot acquire FSA issuer permissions by triggering itself or modifying a public branch. The FSA must bind the newly created GitHub run ID in its protected second-stage decision and refuse reruns or drift.

There is no active FSA, no default-branch scientific workflow, no external protected monotonic first-use and dispatch ledger, no OIDC-verifying issuer, no signing secrets and no experiment worker in this source branch. R10 **does not** attempt deployment, merge, cloud provisioning, key enrollment, real research or promotion. F1 and F2 original science remains consumed.
