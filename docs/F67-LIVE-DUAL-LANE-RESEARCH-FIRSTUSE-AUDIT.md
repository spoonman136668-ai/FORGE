# F67 — Authentic dual-lane scientific-run evidence versus protected first-use authority

**Scope:** Existing Wingless and Yggdrasil research autonomy is **research-only**, with each repository separately controlling its own active research branch and local continuation workflow. CKB-plane's engineering work-order leases and receipt integrity (F66) are not the two projects' original-science first-use ledger. F67 checks actual GitHub repository branch, state, workflow and evidence-tree records **read-only**. It creates no controller, signer, credential, science worker, researcher, dispatch, Cloudflare write or new research lane.

The two public repositories already expose a frozen `.research-autonomy/config.json` with `authority=research-only` and `ckb_plane_role=governance-only`. F67 first pins their main branch source SHA; then validates exact configuration against the pinned main source, selects the configured active research branch, pins that source SHA and obtains its `.research-autonomy/state.json`. Its self-reported latest successful continuation run ID is verified against **the actual GitHub Actions API** for correct repository, workflow, run ID, main commit, completion and event-time ordering. Its recorded qualified research source commit must exist on GitHub. Evidence folders are inventoried by actual immutable branch tree objects, separately identifying summary/probe and standalone blocked/exception records.

F67 additionally scans the **latest 100 GitHub Actions runs in each repository**; it distinguishes successful completed jobs, failed/cancelled jobs and pending/in-progress/queued jobs, retaining a bounded sample of unresolved run IDs. A run currently pending or in progress must never be recast as completed. Both repositories have thousands of historic workflow runs; the 100-run census is intentionally **not exhaustive**, and ordinary successful research-continuation workflows are not independent, externally signed prospective science-first-use receipts. Prior research qualification summaries may themselves be historical negative, mixed or invalid findings, which must remain evidence, not be silently upgraded to successes.

**Fail-closed acceptance:** malformed/moving branch, missing frozen source, wrong research-only authority, SHA drift, missing qualified commit, forged latest-run metadata, missing scientific evidence tree, ambiguous status or unavailable GitHub API. Read all sources with `GET` requests only using existing public GitHub data and GitHub Actions' short-lived existing `GITHUB_TOKEN`. The exact-head workflow runs adversarial fixture tests and authentic current API observation, then archives a compact content-addressed non-secret report. Do not create a background polling service.

**Boundary after PASS:** F67 would confirm genuine public repository-local continuation activity and observe live uncertain workflows, but **cannot attest** all historical research original first-use events, consumed, active or uncertain seed/lease states, complete scientist authority, fresh signed current CKB epoch or Cloudflare's deployed atomic first-use. The existing CKB controller remains authority=plane generation=6; last F66 read-only qualification verified 131 `COMPLETED` engineering queue states and four old accepted-work-order attempts with intact receipt hashes, but those cannot be used to authorize protected scientific execution. FORGE's R35/R38 D1 first-use table is still not live per F62/F63 authenticated Cloudflare observations. Worker first-use release and cutover stay false, and historical S14 stays irrevocably consumed.

**Operational F68, not another audit loop:** join original-science signed execution receipts and separate both-lane active/uncertain seed leases from the **actual** per-lane research controllers into the sole existing owner; reconcile incomplete and failed run dispositions by sealed source/experiment IDs, not status guesses; secure an independently authenticated fresh current-owner original decision; verify a private D1 recovery checkpoint; then qualify one atomic live first-use transaction and existing-worker permit before automatic successor dispatch. No replay of unknown first-use, no extra signing credentials by default, no paid model API/Codex routine review, and no unrelated KTRADE mutation.
