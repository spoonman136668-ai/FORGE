## Minimum viable operating architecture — no three dedicated research machines

**Compute:** independent Wingless/Yggdrasil Go worker jobs on public FORGE GitHub-hosted runners. Cap CPU/job duration, reserve one-use original cohort only via FSA, do not use the public runner as a signer.

**Authority and state:** a *separately controlled*, operator-approved managed provider/service should host the protected FSA signing/registration policy, linearizable conditional first-use and dispatch commitments, rollback-resistant audit/log floor, and independently retained immutable evidence. These are security **properties**, not necessarily three always-on virtual machines. Verify true control and failure independence and protection against compromised public GitHub workflow credentials. Do not weaken the existing issue #20 standard without a separate justified policy approval.

**One concrete candidate, not yet chosen or provisioned:** AWS IAM OIDC federation for a narrowly pinned FORGE workflow + IAM-permission-separated AWS KMS asymmetric signer + DynamoDB strongly consistent conditional / transactional first-use and dispatch records + S3 Object Lock immutable raw evidence with independent audit/retention access. Check whether those pieces jointly satisfy independent domain, compromise, rollback and physical-fault requirements; listing AWS products does **not** prove it. AWS OIDC supports role sessions without stored long-lived cloud keys, but a generic role assumed by untrusted public workflow code must have **no signing, CAS, policy modification or promotion permissions**. An FSA-controlled issuer, not the public science worker, must own those rights.
